## Interpretive Principles Applied

The following A1 interpretive principles were applied consistently throughout the audit:

- **Named method/constructor dispatch is not inline domain logic.** Calling `ProviderClientError::host_transport(...)`, `WakeDiagnostic::status("busy")`, `serde_json::to_value(...)`, `uuid::Uuid::new_v4()`, and similar named associated functions or constructors is pure helper dispatch, not inline domain logic that would elevate the classification.
- **Static SQL string literals are not inline SQL construction.** `conn.prepare("SELECT ...")` with a fixed string is an accessor operation. Only dynamically composed SQL fragments would count as inline SQL construction.
- **Trivial inline ops do not trigger HIGH.** `Option::?`, `Result::?`, `.unwrap_or`, `.unwrap_or_else` with literals, `.to_string()`, `.display()`, `format!()` whose arguments are all helper return values or trivial display ops, pure control-flow (`match`, `if let`, `for...in`, `?`) are all trivial inline ops that do not add a category.
- **Inline closures dispatching only to named functions are pure control flow.** A closure `|x| named_fn(x)` used inside an iterator chain is treated as pure dispatch, not inline domain logic.
- **Struct literal construction with helper return values as fields is trivial.** Building a struct whose field values all come from named helper calls does not add a mapper category to a function that is otherwise orchestration.
