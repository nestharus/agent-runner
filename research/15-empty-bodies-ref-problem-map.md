## 2. Already-risky/brittle behavior

- `session_turns` is metadata-only today. Fresh schema lacks body/content/payload and the RCA red run shows actual columns as `id`, provider/session/turn/timestamp/role/parent/sidechain/compaction/source/ingested (`research/12-empty-bodies-ref-rca.md:256-268`).
- Batch ingest depends on provider JSONL references indirectly and usually persists no usable `source_file`: `ingest_session_turns_batch` inserts `source_file = ''` (`src-tauri/src/state/db.rs:2607-2620`), while Codex synthesized `turn_id` embeds `<path>:<line>` in adapter output (`scripts/codex-turns:7-10`, `scripts/codex-turns:81-86`).
- Turn-script adapters currently drop body bytes at two boundaries: the reference scripts do not emit bodies (`scripts/claude-code-turns:77-85`, `scripts/codex-turns:81-86`), and `ScriptTurn` would ignore extra body fields anyway (`src-tauri/src/sessions/mod.rs:32-45`).
- Export depends on JSONL existence. `read_canonical_transcript` immediately reads `metadata.jsonl_path`; missing files produce an operational error (`src-tauri/src/session_export/mod.rs:88-98`). RC-3 captures the user-visible failure: exit 1 with `failed to read transcript ... No such file or directory` (`research/12-empty-bodies-ref-rca.md:326-348`).
- `--inline-transcript` contradicts user expectation: `TraceNode.transcript: Option<()>` plus `then_some(())` means the field is always JSON `null` when requested (`src-tauri/src/trace/mod.rs:33-40`, `src-tauri/src/trace/mod.rs:134-160`), and README documents the placeholder (`README.md:447-451`).
- Import-replace mutates the provider transcript first and then rewrites DB summary rows. The DB transaction is internally atomic, but its rows still omit content and reset canonical v1 lineage fields by design (`src-tauri/src/session_replace/mod.rs:536-574`, `src-tauri/src/session_replace/mod.rs:883-900`).
- Metadata resolution for locate/export/replace is brittle around paths: `available_jsonl_path` requires an absolute existing canonical UTF-8 path (`src-tauri/src/session_metadata/mod.rs:213-255`), Claude workspace derivation can fail with `no_existing_path_hash_decomposition` or `ambiguous_path_hash` (`src-tauri/src/session_metadata/mod.rs:325-334`), and Codex workspace derivation opens JSONL to find `cwd` (`src-tauri/src/session_metadata/mod.rs:390-456`).
- Schema migration style is not centralized by `user_version` in `StateDb`; idempotent column checks coexist with schema-probe's separate `PRAGMA user_version` compatibility reporting (`src-tauri/src/state/db.rs:1017-1061`, `src-tauri/src/schema_probe/mod.rs:95-151`). The WU-13-01 topology migration is already idempotent and should remain so (`src-tauri/src/state/db.rs:1099-1137`).

## 4. Supported / user-reachable paths through the touched surface

- `agents` top-level execution reaches this surface after a successful provider run. `run_with_balancing` starts/finalizes an invocation, then calls `ingest_and_emit_session_id`, which runs the configured turn script and stores parsed turns (`src-tauri/src/main.rs:1982-2100`, `src-tauri/src/main.rs:1059-1090`).
- `agents resume` / top-level resumed execution also reaches ingest after success through the same helper, with a fallback to emitting the known resumed session id (`src-tauri/src/main.rs:1880-1979`).
- `agents session export <session-id>` resolves the owner, reads provider JSONL, and emits canonical JSONL today (`src-tauri/src/main.rs:726-771`). User-visible expectation for this WU: if JSONL is present, canonical bytes remain the same; if JSONL is missing and DB bodies exist, export has a new DB-backed fallback (`tmp/scratch/wu-15-01/ticket.md:85-90`).
- `agents session import-replace <session-id>` reads canonical JSONL input, replaces provider JSONL, then replaces DB turn rows in a transaction today (`src-tauri/src/session_replace/mod.rs:417-574`, `src-tauri/src/session_replace/mod.rs:865-928`). User-visible expectation: body bytes join that atomic DB row replacement without weakening the existing receipt/lock/preimage behavior (`tmp/scratch/wu-15-01/ticket.md:78-104`).
- `agents trace --json --inline-transcript` currently returns `transcript: null`; user-visible expectation is non-null transcript data when body is stored in DB, and `null` plus body-state indication for legacy/no-body rows (`tmp/scratch/wu-15-01/ticket.md:92-98`).

## 5. Cross-platform considerations

- The ticket notes recommend TEXT for v1 and identify BLOB as a later multimodal question (`tmp/scratch/wu-15-01/ticket.md:208-214`). Existing export/import paths already treat transcript and canonical input as UTF-8 text: export rejects non-UTF-8 JSONL lines (`src-tauri/src/session_export/mod.rs:327-332`), import-replace rejects non-UTF-8 input (`src-tauri/src/session_replace/mod.rs:425-429`), and both reference turn scripts open files with `encoding="utf-8"` (`scripts/claude-code-turns:57-60`, `scripts/codex-turns:56-60`). SQLite TEXT storage is not OS-path dependent; current cross-platform risk is mainly Rust/string validation and path handling, not TEXT vs BLOB storage class.
- DECISIONS D-002 says multimodal canonical-record schema expansion is out of v1 and text-only records are the current contract (`DECISIONS.md:34-57`). I found no touched-surface evidence that forces BLOB sooner; binary/multimodal bodies remain an open proposal decision, not an existing-code requirement.
- OS-specific/path-sensitive logic exists in metadata, not in the body storage code boundary: `PathBuf` canonicalization and UTF-8 path checks (`src-tauri/src/session_metadata/mod.rs:213-255`), Claude path-decomposition (`src-tauri/src/session_metadata/mod.rs:257-388`), Codex JSONL `cwd` derivation (`src-tauri/src/session_metadata/mod.rs:390-456`), and Unix-only RCA harness entrypoint (`src-tauri/tests/empty_bodies_ref_rca.rs:1-4`).
- Bun/frontend tests should be unaffected because the ticket excludes `src/` and no touched surface is frontend (`tmp/scratch/wu-15-01/ticket.md:151-156`). This map found no `src/` call site in the body-storage path.

## 7. Open questions / unknowns

- Body column type remains a proposal choice. The ticket recommends TEXT for v1 (`tmp/scratch/wu-15-01/ticket.md:208-214`), and D-002 defers multimodal/binary round-trip schema (`DECISIONS.md:34-57`), but this map does not choose TEXT vs BLOB.
- Body column name remains a proposal choice. Surrounding canonical export names the body-bearing field `content` (`src-tauri/src/session_export/mod.rs:8-18`), RCA fixtures use `content` for seeded body JSON (`src-tauri/tests/empty_bodies_ref_rca/mod.rs:77-84`), while the ticket allows `body`, `content`, or `payload` (`tmp/scratch/wu-15-01/ticket.md:69-76`). This map does not choose the name.
- Existing adapters do not already emit usable body fields. `claude-code-turns` emits summary/lineage fields only (`scripts/claude-code-turns:77-85`), and `codex-turns` emits summary fields only (`scripts/codex-turns:81-86`).
- Export canonical-record bytes are transformed from provider JSONL today, not provider-line passthrough: it parses UTF-8 JSON, normalizes content chunks, computes source metadata, then serializes compact JSON (`src-tauri/src/session_export/mod.rs:311-355`, `src-tauri/src/session_export/mod.rs:405-460`, `src-tauri/src/main.rs:759-770`). The DB fallback must be evaluated against that existing canonical serializer, but this map does not design how identical bytes are reconstructed.
- Import-replace's transaction shape appears mechanically able to add another inserted column because `replace_db_turns` already owns the delete/insert/update transaction in one function (`src-tauri/src/session_replace/mod.rs:865-928`). Whether body data should be derived from `CanonicalRecord.content`, raw canonical JSON, or provider-native rendering is a Phase 3/5 design question.
- If `user_version` must be bumped for the body migration, the ticket's code boundary may be missing `src-tauri/src/schema_probe/mod.rs` and schema-probe fixtures. Current `StateDb` migrations do not update `PRAGMA user_version`; schema-probe separately defines version 3 and required columns (`src-tauri/src/schema_probe/mod.rs:7-8`, `src-tauri/src/schema_probe/mod.rs:217-231`).
