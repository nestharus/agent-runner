## 2. Atomic Replace and Crash-Recovery Terrain

1. The closest existing atomic-replace precedent is `migrate_chain_segment`, not a general import API. It resolves a source/target provider pair, locates source JSONL, reads bytes, optionally slices from the latest compaction boundary, writes a target JSONL temp file, renames it, then updates DB segment rows. (`src-tauri/src/migration/mod.rs:79-214`, `:216-254`)
2. Migration uses a same-directory temp path derived by `target_path.with_extension("jsonl.tmp")`, writes bytes with `std::fs::write`, and performs `std::fs::rename` to the target path. (`src-tauri/src/migration/mod.rs:195-214`)
3. Migration does not fsync the temp file, fsync the directory, use a unique temp name, record a pending operation, or clean up a leftover temp file before starting. (`src-tauri/src/migration/mod.rs:206-214`)
4. Migration mutates the filesystem before mutating the DB: target JSONL rename happens before `close_active_segment_returning` and `open_chain_segment`. A crash between rename and segment updates can leave transcript storage and chain state out of sync. (`src-tauri/src/migration/mod.rs:206-231`)
5. Migration has one concurrency check before file write: `find_conflicting_active_segment` rejects a target provider/session that is already active in another chain. It does not guard the whole source-read, target-write, rename, and DB-update sequence. (`src-tauri/src/migration/mod.rs:196-204`, `src-tauri/src/state/db.rs:2404-2425`)
6. Migration detects a concurrently closed segment only after the rename, when `close_active_segment_returning` returns no row. (`src-tauri/src/migration/mod.rs:216-222`, `src-tauri/src/state/db.rs:2474-2498`)
7. Current crash-surviving state after a migration crash is only whatever reached the filesystem and SQLite before the crash: an optional `.jsonl.tmp`, an optional renamed target JSONL, and optional DB segment updates. There is no durable transaction marker connecting them.
8. Current open-path recovery does not mention transcript temp files. `StateDb::open` repairs/migrates DB schemas and backfills chains, but it does not scan provider transcript directories or lock directories for pending replace/migration artifacts. (`src-tauri/src/state/db.rs:431-608`)
9. Pause-handshake's lock writer is the existing fsync/unique-temp precedent in the stacked branch, but it is scoped to JSON lock metadata, not transcript replacement or DB row updates. (`06-pause-handshake/src-tauri/src/session_lock/mod.rs:263-308`)
10. There is no current import-replace pending-op table, temp filename convention, marker file, receipt log, or recovery command. Searches in this worktree find no `import-replace`, `preimage`, `postimage`, or `session_locks` implementation. (`src-tauri/src`)
11. The requested two-phase sequence includes temp write, fsync, rename, and DB update. Current migration covers temp write and rename only; state DB updates are separate SQLite statements outside a transcript-file transaction. (`03-session-import-replace.md`, `src-tauri/src/migration/mod.rs:206-231`)
12. The requested preimage check has no existing analogue in migration. Migration reads the source transcript for copying/slicing but does not hash and compare the full current transcript before mutation. (`src-tauri/src/migration/mod.rs:162-186`)
13. The requested postimage receipt has no existing analogue in migration. Migration returns `MigratedSegment` with chain/provider/session/path/reason, but no before/after content hash. (`src-tauri/src/migration/mod.rs:244-253`)
14. Current SQLite transactions are used inside individual DB helpers such as batch ingestion and chain minting, but migration's file rename and segment updates are not enclosed by one higher-level transaction boundary. (`src-tauri/src/state/db.rs:1265-1284`, `:2179-2226`, `src-tauri/src/migration/mod.rs:206-231`)
15. `close_active_segment_returning` updates `last_turn_id` by querying `session_turns` at close time. A transcript replace that changes turns without matching state updates can leave future segment close operations recording stale turn ids. (`src-tauri/src/state/db.rs:2474-2498`)
16. Current recovery after a leftover migration temp file is undefined by code. A later migration attempt uses the same `.jsonl.tmp` path and `std::fs::write`, so an old temp can be overwritten rather than classified as a pending operation. (`src-tauri/src/migration/mod.rs:206-214`)
17. Current recovery after a renamed transcript but failed DB update is also undefined. The resolver still reads the old active segment state, while the target/source JSONL files may already reflect the attempted mutation. (`src-tauri/src/migration/mod.rs:206-231`, `src-tauri/src/state/db.rs:2577-2764`)

## 3. Currently Risky or Brittle Behavior

1. There is no current public or internal import-replace command. Any current replacement of provider JSONL and session rows would be ad-hoc direct filesystem/SQLite mutation outside the binary's supported surface.
2. `StateDb::open_default` is mutating, so a command that needs to preflight schema compatibility before transcript mutation cannot get today's default DB path without potentially creating or changing state. (`src-tauri/src/state/db.rs:431-615`)
3. The schema-probe branch reports `safe_for_import_replace = false` until both `session_import_replace` and `session_pause_handshake` features are present. That reflects a stacked-feature dependency, not a capability in this local worktree. (`06-schema-probe/src-tauri/src/schema_probe/mod.rs:173-206`)
4. `session_turns` cannot be reconstructed into canonical input/output because it stores summary fields only. It has no message content, source byte offsets, line hashes, or unsupported-record detail. (`src-tauri/src/state/db.rs:559-572`, `06-export/src-tauri/src/session_export/mod.rs:8-34`)
5. Batch ingestion writes `source_file = ''`, so even existing transcript provenance in DB is usually absent. (`src-tauri/src/state/db.rs:2171-2228`)
6. `resolve_resume` can collapse multiple historical candidates to one by 24-hour recency or max `last_used_at`; import-replace would inherit that ambiguity behavior if it shares the mandated resolver. (`src-tauri/src/state/db.rs:2713-2749`)
7. Multiple active segments for one chain are not schema-invalid today; the latest row wins. That makes "exclusive ownership" stricter than current resume ownership. (`src-tauri/src/state/db.rs:2751-2764`)
8. Current `running` invocation rows are not reliable session-busy locks: they may have no session id before provider spawn, can survive process kill, have no TTL/token, and are not checked by resume/migration. (`src-tauri/src/main.rs:971-984`, `:1173-1182`, `src-tauri/src/state/db.rs:826-854`)
9. Provider child processes write provider-native transcript files outside SQLite transaction boundaries. The runner records invocation/session rows around the spawn but does not persist child pid/session-writer ownership. (`src-tauri/src/main.rs:990-1007`, `:1187-1199`)
10. Balanced one-shot execution may discover a session only after provider execution and turn-script scanning, so not every writer has a known session id before spawn. (`src-tauri/src/main.rs:1317-1393`)
11. `scan_provider` and post-success ingestion can mint turns and chains after provider execution; those writes are partial-tolerant and continue with warnings on many adapter errors. (`src-tauri/src/main.rs:541-615`, `src-tauri/src/sessions/mod.rs:55-141`)
12. `locate_transcript` creates the adapter `STATE_DIR` even on read-like path lookup, which is weaker than export/import preflight expectations that distinguish read-only checks from mutation. (`src-tauri/src/sessions/mod.rs:183-187`)
13. Claude and Codex JSONL shapes differ materially. Claude records use top-level `sessionId`, `type`, `uuid`, and content/message fields; Codex rollout files use `session_meta` plus `response_item.payload` message records. (`06-export/src-tauri/src/session_export/mod.rs:101-164`, `:166-236`)
14. Claude export currently skips provider records without `sessionId`, rejects a mismatched present `sessionId`, and truncates output to the latest compact summary boundary when present. These are canonical-reader semantics import-replace must not accidentally reinterpret as DB rows. (`06-export/src-tauri/src/session_export/mod.rs:108-163`)
15. Codex export currently requires a matching `session_meta.payload.id`, uses message payload ids when available, and synthesizes turn ids from path/line when absent. (`06-export/src-tauri/src/session_export/mod.rs:173-235`)
16. Storage type naming is split between config serde (`codex`) and public metadata/export (`codex_session`). No backwards-compatibility shim exists in this worktree. (`src-tauri/src/config/model.rs:195-200`, `06-export/src-tauri/src/session_export/mod.rs:36-52`)
17. There is no current structured stderr JSON mapping for import-replace's full error namespace. Resume emits human text for most resolver failures; locate/export/pause branches add structured session errors on their own surfaces. (`src-tauri/src/main.rs:658-707`, `06-export/src-tauri/src/main.rs:504-550`, `06-pause-handshake/src-tauri/src/main.rs:914-970`)
18. Current config loading behavior differs across paths. Resume/repl default missing or malformed providers/sessions config in some places, while trace treats malformed sessions config as an error; import-replace sits closer to locate/export where storage and locator config are part of preflight. (`src-tauri/src/main.rs:447-458`, `:826-829`, `:1079-1084`)
19. `locate_transcript` accepts any single stdout line as a path in this worktree; stricter absolute/canonical/existing path checks live in the stacked locate metadata layer. (`src-tauri/src/sessions/mod.rs:171-199`, `06-locate/src-tauri/src/session_metadata/mod.rs:200-242`)
20. Export buffers all canonical JSONL into a `String` before printing, which gives "no partial transcript on parse error" for export. There is no equivalent current buffering/atomicity precedent for a mutating stdin/from-file import path. (`06-export/src-tauri/src/main.rs:529-549`)

## 5. Supported / User-Reachable Paths and Session-Busy Signals Today

1. `agents repl <model>` launches an interactive provider, records invocation state, finalizes, and may ingest/emits session state after success. (`src-tauri/src/main.rs:809-1054`)
2. `agents repl <model> --resume <UUID>` resolves the active segment, may migrate it, records a resumed invocation using the caller-supplied id, then passes the resolved active provider session id to the provider. (`src-tauri/src/main.rs:830-1007`)
3. `agents resume -m <model> --session-id <UUID>` reads answer input, resolves owner, may migrate, records a resumed invocation, passes `resolved.active_session_id` to the provider, and ingests/emits state after success. (`src-tauri/src/main.rs:1056-1263`)
4. Top-level `agents -m <model> --resume <UUID> ...` routes into `run_resume`; top-level `agents --resume <UUID>` with no prompt routes into `run_repl`. (`src-tauri/src/main.rs:341-389`)
5. `agents -m <model> <prompt>` and file/stdin one-shot execution route through balanced execution and can create/update session state after provider execution. (`src-tauri/src/main.rs:390-445`, `:1265-1411`)
6. `agents migrate-db` is user-reachable and mutates chain/compaction state. (`src-tauri/src/main.rs:1450-1462`)
7. Hidden `agents resume-list <UUID>` reads chain previews and recent turns but is lock-blind and human-text only. (`src-tauri/src/main.rs:155-157`, `src-tauri/src/main.rs:1887-1900`)
8. Direct provider CLI usage outside agent-runner becomes visible through adapter scans, which can mint imported chains later resolved by locate/export/import. (`src-tauri/src/sessions/mod.rs:55-141`)
9. The clearest future session-busy signal from stacked work is an unexpired `SessionLock` for the resolved active session id. It currently rejects only another pause acquisition, not the local resume/repl writers. (`06-pause-handshake/src-tauri/src/session_lock/mod.rs:100-148`, `06-pause-handshake/src-tauri/src/main.rs:844-865`)
10. Current DB state has weak in-flight signals: `invocations.status = 'running'`, possibly `invocations.session_id`, and active chain segments. These are not exclusive leases, are not TTL-cleaned, and may not identify the provider-native write target. (`src-tauri/src/state/db.rs:826-854`, `src-tauri/src/main.rs:971-984`, `:1173-1182`)
11. Current exclusivity can be disproven by multiple recent candidate chains, no active segment, provider/model mismatch, unsupported storage/path state, or a conflicting active segment in another chain. Only migration has a helper for one of those conflicts. (`src-tauri/src/state/db.rs:2577-2670`, `:2404-2425`)
12. There is no current single predicate for "session is idle and exclusively owned by import-replace." The existing terrain has resolver ownership, optional lock lease state on the stacked branch, running invocation rows, provider child processes, and provider-native files as separate signals.
13. A current `running` invocation can be finalized by `FinalizerGuard` on normal drop/unwind, but hard process death bypasses that guard. Surviving running rows therefore mix live work and stale process state. (`src-tauri/src/main.rs:502-535`)
14. `run_repl --resume` and `run_resume` record the user-supplied resume id in `invocations.session_id`, while provider execution uses `resolved.active_session_id`. For migrated or chain-id inputs, the DB row can differ from the provider-native write target. (`src-tauri/src/main.rs:982-999`, `:1181-1198`)
15. The pause-handshake branch acquires locks on `resolved.active_session_id`, not necessarily the raw user input. That matters for busy checks when the input is a chain id or an alias that resolves to an active provider session id. (`06-pause-handshake/src-tauri/src/main.rs:826-848`)

## 6. Migration / Pre-Existing-State Implications

1. Pre-existing sessions may have chain/segment ownership but missing, moved, or malformed JSONL. Resume can still target them by provider resume strategy; locate/export/import require current path availability. (`src-tauri/src/state/db.rs:2577-2670`, `06-locate/src-tauri/src/session_metadata/mod.rs:200-242`)
2. Pre-chain or partially migrated DBs can contain `session_turns` rows without segment membership. Since resolver candidates come from segments only, import-replace would see not-found for those ids through the shared ownership path. (`src-tauri/src/state/db.rs:2256-2271`, `:2696-2711`)
3. Existing chain rows can have `model_name = '<unknown>'`, especially for direct-CLI imported chains. Model inference then depends on invocation history or provider runtime config. (`src-tauri/src/sessions/mod.rs:125-141`, `src-tauri/src/state/db.rs:2616-2626`)
4. Providers without `session_storage` are valid today and can be present in chain state. Locate maps absent storage to `other` and can reject when workspace/path requirements are not met. (`src-tauri/src/config/providers.rs:35-48`, `06-locate/src-tauri/src/session_metadata/mod.rs:31-39`, `:101-119`)
5. Codex storage is declared in config, but current migration explicitly defers Codex source/target migration. Export can parse Codex canonical records on its branch, so import-replace inherits a storage-type split that migration does not handle. (`src-tauri/src/migration/mod.rs:112-118`, `06-export/src-tauri/src/session_export/mod.rs:166-236`)
6. Claude compaction state exists both in DB summaries and in export/migration behavior. Migration slices source bytes from the latest DB compaction boundary, while export skips canonical records before the latest native compact summary record. (`src-tauri/src/state/db.rs:2510-2536`, `src-tauri/src/migration/mod.rs:166-186`, `06-export/src-tauri/src/session_export/mod.rs:151-163`)
7. Replacing a transcript can require DB row changes for `session_turns` because those rows mirror turn ids, roles, timestamps, sidechain/compaction flags, and provider/session ownership. No current helper replaces a whole session's turn set from canonical JSONL.
8. Replacing a transcript can affect `session_chains` because `last_used_at` and `model_name` are resolver inputs or previews; current helpers update last-used or model in narrow invocation/migration cases only. (`src-tauri/src/state/db.rs:1243-1263`, `:2500-2508`, `:2713-2749`)
9. Replacing a transcript can affect `session_chain_segments` because the active provider/session and `last_turn_id` are the resolver and migration ledger. Current helpers close/open segments or mint imported segments, but none rewrites one existing active segment in place from a canonical transcript. (`src-tauri/src/state/db.rs:2365-2498`)
10. Current indexes used by resume/export metadata expect segment lookup by session id, active segment lookup by chain/ended-at, and invocation lookup by provider/session. A partial replace that leaves rows inconsistent can make later resume/export select stale owners. (`src-tauri/src/state/db.rs:594-597`, `:869-877`, `:2577-2764`)
11. There is no persisted "last known good transcript hash" or "current canonical transcript hash" field. Preimage verification must be based on reading the existing JSONL bytes/records at operation time, not DB metadata.
12. There is no persisted postimage hash. Existing receipts (`OULIPOLY_SESSION`, trace JSON, export JSONL, pause receipt, migration stderr) do not record transcript content hashes. (`src-tauri/src/main.rs:610-615`, `src-tauri/src/trace/mod.rs:59-80`, `06-pause-handshake/src-tauri/src/main.rs:849-863`)
13. `session_turns` uniqueness is `(provider_name, session_id, turn_id)`. A replace that changes turn ids, removes turns, or rewrites Codex synthesized ids would need state consistency beyond insert-only ingestion. (`src-tauri/src/state/db.rs:559-572`, `06-export/src-tauri/src/session_export/mod.rs:201-208`)
14. `session_chain_segments` uniqueness is `(chain_id, provider_name, session_id)`. Current helpers can reopen an existing segment or mint a new one, but they do not model "same owner, replaced transcript contents" as a separate durable state. (`src-tauri/src/state/db.rs:581-592`, `:2365-2402`)
15. `session_chains.last_used_at` participates in ambiguity resolution. Replacing an old transcript without carefully accounting for `last_used_at` could change or fail to change future owner selection in user-visible ways. (`src-tauri/src/state/db.rs:574-579`, `:2713-2749`)
16. Pre-existing lock files from pause-handshake, if that branch lands first, live outside SQLite under the data-dir `locks` path. They are not represented in `schema-probe` DB tables and are not visible through `resolve_resume`. (`06-pause-handshake/src-tauri/src/main.rs:908-912`, `06-pause-handshake/src-tauri/src/session_lock/mod.rs:238-244`)

## 7. Observability Gaps and Assumption Register Draft

1. Gap: there is no command that reports "this session is safe to import-replace now." Schema-probe can report `safe_for_import_replace` on its branch, but the local worktree has no probe or import feature flag. (`06-schema-probe/src-tauri/src/schema_probe/mod.rs:154-206`)
2. Gap: there is no durable replace journal, pending-temp cleanup report, or recovery receipt. After a crash, users can inspect files and SQL manually, but the binary has no import-replace recovery state.
3. Gap: there is no current stdout JSON receipt for a transcript mutation with `preimage_sha256`, `postimage_sha256`, `state_updated`, and `committed_at`.
4. Gap: there is no current structured distinction between invalid canonical input, preimage mismatch, malformed existing provider transcript, and schema incompatibility on one mutation command.
5. Gap: there is no current test fixture surface in this branch for import-replace crash injection points; migration tests cover migration behavior, while export/pause branches own canonical reader and lock tests.
6. A1: Import-replace will consume the earlier Initiative 06 surfaces after they land: locate metadata, schema-probe read-only compatibility, export canonical reader, and pause-handshake lock API. Evidence: initiative sequencing places import-replace last and the harness contract says it composes those features. Invalidator: import-replace is rebased directly onto this local worktree without those merged APIs. (`06-session-override-contract.md`)
7. A2: `StateDb::resolve_resume` remains the ownership resolver for import-replace. Evidence: Initiative 06 cross-feature constraints require it, and locate/export/pause branches use or wrap it. Invalidator: an earlier merged feature changes public session ownership away from chain/segment resume semantics. (`src-tauri/src/state/db.rs:2577-2670`)
8. A3: The canonical transcript input family is exactly the export branch's `CanonicalRecord` JSONL, not provider-native JSONL and not `session_turns`. Evidence: harness anti-scope excludes provider-native JSONL as public input, and export defines canonical records with source metadata. Invalidator: the export contract changes before import-replace starts. (`03-session-import-replace.md`, `06-export/src-tauri/src/session_export/mod.rs:8-34`)
9. A4: Preimage verification is over the current canonical transcript representation or its current JSONL source as finally specified by export/import contract, not over summary DB rows. Evidence: DB rows lack content/source hashes, and the harness names current canonical transcript hash. Invalidator: the proposal defines preimage hash over a different stable byte stream with explicit user approval. (`src-tauri/src/state/db.rs:559-572`, `03-session-import-replace.md`)
10. A5: Storage type remains the discriminator for Claude vs Codex parser/replacement behavior. Evidence: locate/export map provider `SessionStorage` to public storage types and parser selection. Invalidator: providers can return a JSONL path whose native shape disagrees with configured storage. (`src-tauri/src/config/model.rs:195-229`, `06-export/src-tauri/src/session_export/mod.rs:88-99`)
11. A6: Current running invocation rows are insufficient by themselves for `session-busy`. Evidence: they are not tokenized leases, may not target a known session before spawn, and can remain after hard process death. Invalidator: a preceding feature changes invocation lifecycle into durable active-writer leases. (`src-tauri/src/main.rs:971-984`, `:1265-1393`)
12. A7: Crash recovery is not already supplied by migration's temp-file path. Evidence: migration has temp write and rename but no fsync, journal, unique pending marker, or cleanup pass. Invalidator: a prior merged change refactors migration into a recoverable lower-level replace primitive before import-replace proposal work. (`src-tauri/src/migration/mod.rs:206-231`)
13. A8: State consistency after replace must cover at least `session_turns`, `session_chains`, and `session_chain_segments` because those tables drive export/resume lookup and previews. Evidence: schema, resolver, ingestion, and migration helpers all use those rows. Invalidator: a preceding feature introduces a new canonical transcript-state table that supersedes them for import/export. (`src-tauri/src/state/db.rs:559-597`, `:2577-2764`)
14. A9: `--from-file` and stdin should be equivalent at the contract level, but no current code path reads canonical transcript JSONL from either source. Evidence: existing file/stdin readers are prompt/answer readers or provider stdout writers. Invalidator: a preceding feature adds shared canonical transcript input loading before import-replace. (`src-tauri/src/main.rs:341-389`, `:1056-1071`)
15. A10: Postimage hash emission is currently a new observability field rather than reuse of an existing receipt field. Evidence: existing session receipts carry ids, providers, paths, or lease tokens, but not transcript content hashes. Invalidator: export or schema-probe gains a stable transcript-hash output before import-replace. (`src-tauri/src/main.rs:610-615`, `06-pause-handshake/src-tauri/src/main.rs:849-863`)
16. This map deliberately does not design the replace protocol, recovery marker format, DB transaction shape, lock-acquisition order, canonical input validator, or parser-to-state mapping.
