## Current behavior of the touched surface

- `select_provider` returns index `0` for zero/one provider, otherwise optionally refreshes stale providers and scans session logs when a `BalanceContext` is supplied (`src-tauri/src/balancer/mod.rs:93`-`src-tauri/src/balancer/mod.rs:113`). It then reads `provider_quotas` and `provider_quota_windows` from SQLite and filters out providers with `exhausted_at` set (`src-tauri/src/balancer/mod.rs:116`-`src-tauri/src/balancer/mod.rs:138`).
- If every candidate is exhausted, `select_provider` picks the provider with the oldest `exhausted_at` and returns it as a best-guess route rather than restoring all candidates (`src-tauri/src/balancer/mod.rs:139`-`src-tauri/src/balancer/mod.rs:157`).
- If every non-exhausted candidate has at least one window, the balancer uses density scoring; if any candidate has zero windows, it falls back to invocation-count scoring (`src-tauri/src/balancer/mod.rs:160`-`src-tauri/src/balancer/mod.rs:167`).
- `is_stale` is provider-local. Missing quota rows are stale; quota rows without `refreshed_at` are stale; quota rows with zero windows are stale. Otherwise staleness is only `age_secs >= dynamic_ttl_secs(provider_windows)` (`src-tauri/src/quota/mod.rs:187`-`src-tauri/src/quota/mod.rs:200`).
- `dynamic_ttl_secs` uses the provider's own minimum remaining reset duration divided by five and clamps the result to 5 minutes through 24 hours (`src-tauri/src/quota/mod.rs:206`-`src-tauri/src/quota/mod.rs:217`). It does not compare sibling topology.
- Density scoring calls `compute_projections_from_records`, turns projections into `ProviderEval`s, filters out unlearned providers, and returns `best_binding_score(...).index` (`src-tauri/src/balancer/mod.rs:170`-`src-tauri/src/balancer/mod.rs:198`).
- Projection computes the pool maximum live-window count across candidates, then evaluates each provider's live windows (`src-tauri/src/balancer/mod.rs:238`-`src-tauri/src/balancer/mod.rs:259`). Recent provider/model errors at or above `ERROR_THRESHOLD` produce no binding score (`src-tauri/src/balancer/mod.rs:260`-`src-tauri/src/balancer/mod.rs:270`).
- Projection counts assistant turns since the provider's `refreshed_at`; this is the scoring turn input, not `calls_since_refresh` (`src-tauri/src/balancer/mod.rs:272`-`src-tauri/src/balancer/mod.rs:282`).
- The missing-window penalty triggers only when a provider has fewer live windows than the pool maximum and at least one visible live window has `used_percent >= 0.85`; then the binding score is forced down to `0.0` (`src-tauri/src/balancer/mod.rs:288`-`src-tauri/src/balancer/mod.rs:295`).
- For each live window, scoring skips past-reset windows, bootstraps a burn rate, projects usage as `base_used_percent + turns * burn_rate`, computes headroom, and takes the provider binding score as the minimum `remaining_headroom * hours_until_reset` across scored windows (`src-tauri/src/balancer/mod.rs:297`-`src-tauri/src/balancer/mod.rs:327`).
- A provider is unlearned when any scored live window lacks a bootstrapped burn rate or no window is scored; if all eligible density providers are unlearned, the balancer falls back to invocation-count round-robin (`src-tauri/src/balancer/mod.rs:184`-`src-tauri/src/balancer/mod.rs:195`, `src-tauri/src/balancer/mod.rs:324`-`src-tauri/src/balancer/mod.rs:328`).
- Burn-rate bootstrap order is own window rate, sibling average for the same `window_id`, then duration-ratio fallback from a longer learned window (`src-tauri/src/balancer/mod.rs:460`-`src-tauri/src/balancer/mod.rs:542`).
- Learned-quota selection is deterministic argmax over binding score. `best_binding_score` uses `max_by` and has no fanout, score banding, provider history term, or seeded round-robin term (`src-tauri/src/balancer/mod.rs:438`-`src-tauri/src/balancer/mod.rs:454`).
- `upsert_quota_refresh` reads the prior metadata/windows, opens one unchecked transaction, and handles empty input by preserving prior windows and recording `last_empty_refresh_at` (`src-tauri/src/state/db.rs:1885`-`src-tauri/src/state/db.rs:1944`).
- For non-empty refreshes, `upsert_quota_refresh` computes turns since the prior refresh using `count_assistant_turns_since`, falling back to `calls_since_refresh`, clears `exhausted_at`, deletes all old windows, inserts new window rows with fresh positional `window_id`s, and commits (`src-tauri/src/state/db.rs:1947`-`src-tauri/src/state/db.rs:2039`).
- Quota parsing accepts `windows` or legacy single-window output, validates script `used_percent` on a 0..100 scale, and stores 0..1 ratios (`src-tauri/src/quota/mod.rs:329`-`src-tauri/src/quota/mod.rs:373`; README contract at `README.md:320`-`README.md:322`).

## Already-risky or brittle behavior

- Stale-cache topology blind spot: `is_stale` has no sibling comparison and no memory of prior/peak topology. A provider with one fresh weekly window can remain fresh while siblings have two windows, because staleness only checks the provider's own row, own windows, and own TTL (`src-tauri/src/quota/mod.rs:187`-`src-tauri/src/quota/mod.rs:217`).
- Missing-window penalty is gated by visible usage >= `0.85`. The RC-1 shape has a low-used single weekly window, so the current penalty does not trigger even though siblings expose short-window constraints (`src-tauri/src/balancer/mod.rs:12`-`src-tauri/src/balancer/mod.rs:20`, `src-tauri/src/balancer/mod.rs:288`-`src-tauri/src/balancer/mod.rs:295`).
- Learned-quota path is capacity-rank-and-pin. A modestly higher binding score wins all repeated selections until external state changes because `best_binding_score` is plain argmax (`src-tauri/src/balancer/mod.rs:189`-`src-tauri/src/balancer/mod.rs:198`, `src-tauri/src/balancer/mod.rs:438`-`src-tauri/src/balancer/mod.rs:454`).
- Successful invocations increment `calls_since_refresh`, but density scoring ignores that field and projects from ingested assistant turns since `refreshed_at`; if no new turns are scanned/ingested, repeated selections alone do not create distribution pressure in the density path (`src-tauri/src/balancer/mod.rs:272`-`src-tauri/src/balancer/mod.rs:282`, `src-tauri/src/main.rs:2097`-`src-tauri/src/main.rs:2101`, `src-tauri/src/state/db.rs:2116`-`src-tauri/src/state/db.rs:2128`).
- `provider_quota_windows.window_id` is positional. If a provider drops/reorders windows, the delta learner maps current windows to prior windows by index rather than semantic topology (`src-tauri/src/state/db.rs:150`-`src-tauri/src/state/db.rs:152`, `src-tauri/src/state/db.rs:1955`-`src-tauri/src/state/db.rs:1958`, `src-tauri/src/state/db.rs:1987`-`src-tauri/src/state/db.rs:2024`).
- Schema has no topology metadata: `provider_quotas` tracks only provider name, legacy used/resets fields, calls, refresh timestamps, empty-refresh timestamp, and exhaustion timestamp; `provider_quota_windows` tracks only positional windows and delta-learning fields (`src-tauri/src/state/db.rs:520`-`src-tauri/src/state/db.rs:538`).
- Refresh writes replace all windows wholesale on non-empty refresh. This is atomic inside one transaction, but it also means a transient non-empty incomplete response deletes omitted windows and can make the incomplete topology the fresh cache (`src-tauri/src/state/db.rs:1882`-`src-tauri/src/state/db.rs:1884`, `src-tauri/src/state/db.rs:1981`-`src-tauri/src/state/db.rs:2038`).
- Empty refreshes preserve prior windows, but non-empty incomplete refreshes are accepted as ground truth. Auth refresh only retries empty-window responses after prior non-empty windows, not reduced-window responses (`src-tauri/src/quota/mod.rs:164`-`src-tauri/src/quota/mod.rs:181`, `src-tauri/src/state/db.rs:1900`-`src-tauri/src/state/db.rs:1944`).
- The README currently documents "load balanced" but also states `pick = argmax`, which matches the implementation yet conflicts with user expectations for fanout across similarly healthy accounts (`README.md:230`-`README.md:233`, `src-tauri/src/balancer/mod.rs:198`).
- README says providers with 3+ errors are "deprioritized" (`README.md:234`), while the density path filters unlearned/error projections and the fallback path assigns `f64::MAX` or invokes round-robin when all are error-maxed; this is close but not a complete behavioral contract for all exhausted/error combinations (`src-tauri/src/balancer/mod.rs:260`-`src-tauri/src/balancer/mod.rs:270`, `src-tauri/src/balancer/mod.rs:590`-`src-tauri/src/balancer/mod.rs:615`).
- `refresh_quotas` IPC serializes internal 0..1 ratios into a field named `used_percent`; the ticket anti-scope forbids changing this response shape, but it remains a unit-name footgun next to the script contract's 0..100 `used_percent` (`src-tauri/src/lib.rs:291`-`src-tauri/src/lib.rs:303`, `src-tauri/src/lib.rs:357`-`src-tauri/src/lib.rs:365`, `README.md:320`).

## Supported and user-reachable paths through the surface

- Direct CLI invocation path: an end user runs `oulipoly-agent-runner` or the `agents` wrapper with a multi-provider model. `run_with_balancing` opens the default state DB, loads `providers.toml` and `sessions.toml`, creates `InFlight`, builds `BalanceContext`, and calls `select_provider` (`src-tauri/src/main.rs:1967`-`src-tauri/src/main.rs:2000`).
- During `select_provider`, each provider is checked with `is_stale`; stale providers with quota scripts are refreshed synchronously via `refresh_provider`, and session logs are scanned before cached quotas/windows are read (`src-tauri/src/balancer/mod.rs:98`-`src-tauri/src/balancer/mod.rs:126`).
- `refresh_provider` shells out to the configured quota script, optionally runs `auth_refresh_command` and retries, parses JSON windows, and writes them through `upsert_quota_refresh` (`src-tauri/src/quota/mod.rs:114`-`src-tauri/src/quota/mod.rs:162`, `src-tauri/src/quota/mod.rs:268`-`src-tauri/src/quota/mod.rs:373`).
- `upsert_quota_refresh` writes `provider_quotas` metadata and `provider_quota_windows` rows. Empty windows preserve prior rows and update `last_empty_refresh_at`; non-empty windows replace the provider's full window set, reset `calls_since_refresh`, clear `exhausted_at`, and store learned-delta data when the sample passes guards (`src-tauri/src/state/db.rs:1885`-`src-tauri/src/state/db.rs:2039`).
- After refresh/session scan, `select_provider` filters exhausted providers, chooses density scoring if all candidates have windows, or falls back to invocation count. Density scoring computes projected usage/headroom and returns deterministic argmax today (`src-tauri/src/balancer/mod.rs:127`-`src-tauri/src/balancer/mod.rs:198`).
- After execution, the CLI path records success/failure, classifies quota-exhausted stderr and marks the provider exhausted, ingests/records session IDs, then increments `calls_since_refresh` (`src-tauri/src/main.rs:2046`-`src-tauri/src/main.rs:2101`).
- Interactive CLI routing reaches the same `select_provider` and quota refresh surface through a separate path before interactive provider execution (`src-tauri/src/main.rs:1582`-`src-tauri/src/main.rs:1649`).
- UI/IPC observation today is limited. `refresh_quotas` can refresh/read the same quota cache from the Tauri side (`src-tauri/src/lib.rs:309`-`src-tauri/src/lib.rs:381`), but `src/lib/tauri.ts` currently exposes `listPools` and `testModel`, not a frontend `refreshQuotas` wrapper (`src/lib/tauri.ts:51`-`src/lib/tauri.ts:74`). `PoolCard.tsx` renders pool names and command chips, not quota windows (`src/components/PoolCard.tsx:100`-`src/components/PoolCard.tsx:130`); `PoolsView.tsx` has a local variable named `remaining` for command removal, not quota remaining (`src/views/PoolsView.tsx:129`-`src/views/PoolsView.tsx:134`).
- README documents a supported diagnostic example: `quota_check` refreshes stale windows and prints density picks for multi-provider models (`README.md:696`-`README.md:700`).
