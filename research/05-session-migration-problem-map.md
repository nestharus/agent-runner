# Initiative 05 — Existing-State Risk Profile

## 1. Touched Surface Inventory

1. `StateDb::open` owns SQLite schema creation and per-open schema ensures. Today it creates `provider_quotas`, `provider_quota_windows`, and `session_turns`, then runs provider/session ensure helpers before returning the connection wrapper. There is no session-chain layer in the current schema batch; `session_turns` is the only persisted cross-CLI session-log table. (`src-tauri/src/state/db.rs:365-514`)
2. `session_turns` currently stores `(provider_name, session_id, turn_id, timestamp, role, parent_turn_id, is_sidechain, source_file, ingested_at)` with a uniqueness constraint on `(provider_name, session_id, turn_id)`. It has no `is_compaction_boundary` column today. (`src-tauri/src/state/db.rs:493-505`)
3. Existing-DB `session_turns` migration only backfills `parent_turn_id` and `is_sidechain`, then creates lookup indexes. It does not backfill compaction state or any chain metadata. (`src-tauri/src/state/db.rs:598-617`, `src-tauri/src/state/db.rs:764-772`)
4. `SessionTurnRecord` and `SessionTurnIngest` are the Rust-side shapes for ingested turns. Both expose parent and sidechain fields, but neither carries compaction-boundary information. (`src-tauri/src/state/db.rs:97-124`)
5. `ingest_session_turn` inserts a single turn with only provider/session/turn/timestamp/role/source/ingested fields; it does not bind `parent_turn_id` or `is_sidechain`. (`src-tauri/src/state/db.rs:1946-1977`)
6. `ingest_session_turns_batch` inserts turns transactionally and does bind `parent_turn_id` plus `is_sidechain`; it counts only rows newly inserted past `INSERT OR IGNORE`. (`src-tauri/src/state/db.rs:1979-2034`)
7. `scan_provider` shells out to the configured `turn_script`, parses each JSONL line into `ScriptTurn`, converts optional `is_sidechain` to `false` when absent, and batch-ingests all valid lines. Adapter failures and malformed lines become `ScanReport.errors`, not hard failures. (`src-tauri/src/sessions/mod.rs:53-127`)
8. `ScriptTurn` currently accepts `session_id`, `turn_id`, `timestamp`, `role`, optional `parent_turn_id`, and optional `is_sidechain`; adapter scripts emitting other fields are tolerated by Serde but the runner does not persist them. (`src-tauri/src/sessions/mod.rs:32-43`)
9. `find_provider_for_session()` is the current resume resolver. It unions matching rows from `session_turns` and `invocations`, groups by `provider_name`, and orders by latest timestamp descending with provider-name ascending as a tie-break. (`src-tauri/src/state/db.rs:2062-2107`)
10. `ProviderSessionMatch` only carries `provider_name` and `latest_timestamp`; there is no model, chain, active segment, or ambiguity payload in the current resolver result. (`src-tauri/src/state/db.rs:133-137`)
11. `run_repl` validates resume input as a full UUID, calls `find_provider_for_session`, selects `matches[0]`, validates that provider against the requested model's provider pool, and requires that provider to declare `[providers.resume]`. (`src-tauri/src/main.rs:630-727`)
12. `run_resume` repeats the same provider lookup, pool validation, and resume-strategy check for non-interactive one-shot resume. (`src-tauri/src/main.rs:813-885`)
13. The top-level `--resume` dispatcher currently requires `--model <model-id>` before it can decide whether to dispatch to `run_resume` or `run_repl`. (`src-tauri/src/main.rs:309-360`)
14. `resume_model_pool_mismatch_message()` builds suggestions by scanning loaded models for any provider pool containing the resolved provider; the error text is session-id/provider based. (`src-tauri/src/main.rs:599-628`)
15. `ResumeStrategy` supports only `kind = "flag"` and `kind = "subcommand"`. Validation requires exactly the corresponding `flag` or non-empty `subcommand`. (`src-tauri/src/config/model.rs:48-87`)
16. `compose_resume_args()` appends either `<flag> <session_id>` or `<subcommand...> <session_id>` onto provider args. It has no path/config-key resume mode. (`src-tauri/src/executor/cli.rs:241-274`)
17. `execute_resume` disables normal session capture, composes resume args, spawns the provider, then classifies resume acceptance from stdout/stderr rules. Its returned `session_capture` is always `None` because the attempted target is recorded by the caller before spawn. (`src-tauri/src/executor/cli.rs:400-443`)
18. `execute_interactive` composes resume args only when the caller passes a resume payload, then inherits stdio and waits for the child process. (`src-tauri/src/executor/cli.rs:513-550`)
19. `start_invocation`, `update_session_capture`, `update_resume_acceptance`, and `finalize_invocation` are the current lifecycle write path for invocation rows. Session identity is stored directly on `invocations.session_id`; there is no separate conversation identity. (`src-tauri/src/state/db.rs:931-1034`, `src-tauri/src/state/db.rs:1182-1199`)
20. `emit_known_session_id` is the common stderr emission path for known session IDs and writes `session_id` plus capture method to the invocation row before emitting `OULIPOLY_SESSION`. (`src-tauri/src/main.rs:565-584`)
21. `ingest_and_emit_session_id` scans the provider after execution, then heuristically associates a session ID by looking for turns inside the invocation time window. (`src-tauri/src/main.rs:512-563`)
22. `find_session_for_invocation_window` ranks candidate session IDs by the count of turns observed between invocation start and finish, then earliest in-window timestamp, then session ID. (`src-tauri/src/state/db.rs:2109-2162`)
23. `provider_quotas.exhausted_at` already exists as a provider-account global flag and is exposed on `QuotaRecord`. (`src-tauri/src/state/db.rs:63-74`, `src-tauri/src/state/db.rs:389-397`)
24. `mark_exhausted` upserts `exhausted_at`; non-empty quota refresh clears it, while empty-window refresh preserves it. (`src-tauri/src/state/db.rs:1297-1316`, `src-tauri/src/state/db.rs:1380-1424`, `src-tauri/src/state/db.rs:1447-1458`)
25. `select_provider` filters providers whose quota row has `exhausted_at`, then uses density scoring when all remaining candidates have windows; if every provider is exhausted, it returns the oldest exhausted provider index. (`src-tauri/src/balancer/mod.rs:39-119`)
26. `score_by_density` is private and currently both computes per-window projections and selects a provider. Intermediate projected values, hours, and headroom are local variables and are not exposed as a reusable projection object. (`src-tauri/src/balancer/mod.rs:121-244`)
27. The bootstrap cascade for projection uses learned rate, pool same-window average, then duration-ratio fallback. (`src-tauri/src/balancer/mod.rs:277-349`)
28. `ProvidersConfig` currently parses only `quota_script` and `auth_refresh_command`; there is no `default_model` field for UI-started sessions. (`src-tauri/src/config/providers.rs:6-62`)
29. `ProviderConfig` currently parses command, args, interactive args, resume, session capture, and resume acceptance. There is no `[providers.session_storage]` shape. (`src-tauri/src/config/model.rs:6-22`, `src-tauri/src/config/model.rs:286-309`)
30. `SessionsConfig` is adapter-script based and supports `turn_script`, optional `transcript_locator`, and optional `state_dir`. It does not model provider session storage for copying or migration. (`src-tauri/src/config/sessions.rs:6-69`)
31. `locate_transcript` runs a configured `transcript_locator` script at trace time and returns an absolute path, `None`, or an error. It is currently used for trace inspection, not invocation or resume. (`src-tauri/src/sessions/mod.rs:156-184`, `src-tauri/src/trace/mod.rs:311-371`)
32. `TraceSession` emits session ID, capture method, transcript path/state, turn counts, and resume acceptance fields. There is no `chain_id` field today. (`src-tauri/src/trace/mod.rs:59-70`)
33. `build_trace_session` treats missing session IDs as `unresolved`, missing session config as `no_locator`, missing located files as `missing`, and existing files as `available`; locator errors become warnings plus `missing`. (`src-tauri/src/trace/mod.rs:222-371`)
34. `test_model_with_db_path` opens the GUI state DB, selects a provider with no balance context, runs the model, and marks provider exhausted when stderr classifies as exhausted. It does not scan sessions, resolve resume, or touch chains. (`src-tauri/src/lib.rs:498-515`)
35. `quota_check` refreshes quotas, prints cached quota state, and prints per-model provider picks plus window percentages. It does not print session density, chain state, or migration candidacy. (`src-tauri/examples/quota_check.rs:47-147`)
36. `session_scan` is the current manual diagnostic for session ingestion; it scans all configured providers and prints per-provider assistant-turn counts. (`src-tauri/examples/session_scan.rs:1-74`)
37. `scripts/claude-code-turns` reads Claude Code JSONL files by mtime, filters records to `type in ("user", "assistant")`, and emits normalized turns. It silently skips malformed JSON, non-turn records, and unreadable files. (`scripts/claude-code-turns:42-86`)
38. `scripts/codex-turns` reads `rollout-*.jsonl`, discovers `session_meta.payload.id`, and emits message turns with synthetic `turn_id = "<path>:<line_no>"`. It ignores compressed `.jsonl.zst` files and compaction state. (`scripts/codex-turns:41-89`)
39. README's current CLI synopsis presents `repl <model> [--resume <session-id>]` and `resume -m <model> --session-id <session-id>`; the documented public surface is model-required resume. (`README.md:127-136`)
40. README's current resume section describes session lookup across providers through `session_turns`, provider-pool validation, `[providers.resume]`, and the `[resume] -> <provider>` stderr line. (`README.md:416-465`)
41. README's current failure-mode list has four states: no session found, invalid UUID, provider/model mismatch, and provider missing `[providers.resume]`. It has no ambiguous-chain or model-inference failure mode. (`README.md:467-472`)
42. README's `transcript_locator` contract is trace-only today: it fills `transcript_path` and `transcript_state` lazily and does not participate in invocation or resume. (`README.md:324-336`)

## 2. Currently Risky or Brittle Behavior

1. Resume resolution has no true ambiguity state. Multiple provider matches are sorted and `matches[0]` wins; the longer explanation is emitted only for non-TTY stderr. (`src-tauri/src/main.rs:677-690`, `src-tauri/src/main.rs:851-864`)
2. The resolver can only answer "which provider last touched this session ID", not "which logical conversation is active". A migrated or forked conversation is indistinguishable from a same-UUID collision because `ProviderSessionMatch` has no chain or segment identity. (`src-tauri/src/state/db.rs:133-137`, `src-tauri/src/state/db.rs:2069-2081`)
3. No-match resume failures conflate missing ingestion config, missing local transcript state, and genuinely unknown UUID into one user-facing failure. (`src-tauri/src/main.rs:669-675`, `src-tauri/src/main.rs:843-849`)
4. Current top-level resume is a UX cliff for agent workflows because `--resume` rejects before lookup unless `--model` is present. (`src-tauri/src/main.rs:318-321`)
5. `repl --resume` and `resume` both require the resolved provider to be in the requested model's provider pool. That is currently the only protection against resuming a session through the wrong CLI account, but it also blocks continuation when the user picked a model alias whose pool does not include the owner. (`src-tauri/src/main.rs:692-707`, `src-tauri/src/main.rs:866-876`)
6. A provider with no `[providers.resume]` block cannot be resumed even if ingestion found the session and the model pool includes the provider. (`src-tauri/src/main.rs:709-716`, `src-tauri/src/main.rs:878-885`)
7. `compose_resume_args` only understands appending a session ID. Codex's explicit-file resume path is not representable today because there is no config-key or absolute-path argument strategy. (`src-tauri/src/executor/cli.rs:246-274`)
8. Resume attempts record the target session ID before spawn; if the child rejects it, trace can show the attempted target but the session row still looks like a resume-associated invocation unless the consumer checks `resume_acceptance` and exit status. (`src-tauri/src/main.rs:900-917`, `src-tauri/src/trace/mod.rs:228-240`)
9. `execute_resume` disables provider `session_capture`, so a provider that accepts a resume but switches/prints a new actual session ID cannot update the invocation from the child output through the normal capture path. (`src-tauri/src/executor/cli.rs:409-440`)
10. `session_capture_method = "failed"` is observable in trace only as a warning that the reason was logged at execution time; the structured row stores `"failed"` but not the failure detail. (`src-tauri/src/main.rs:1052-1062`, `src-tauri/src/trace/mod.rs:228-232`)
11. `find_session_for_invocation_window` correlates turns to an invocation by timestamps after the fact. Concurrent direct CLI usage on the same provider during the invocation window can produce competing candidates, and the ranking is count/earliest/session-id based. (`src-tauri/src/state/db.rs:2109-2162`)
12. Session ingestion is idempotent at row level, but adapter cursor advancement is outside the DB transaction. A script can emit a batch, update its own cursor, and then fail before the runner commits, or it can crash before writing its cursor after emitting lines. The DB tolerates duplicate re-emission, but it cannot recover skipped rows if the adapter advances too early. (`src-tauri/src/sessions/mod.rs:85-125`, `scripts/claude-code-turns:30-54`, `scripts/codex-turns:29-53`)
13. Batch ingestion is all-or-nothing for database writes, but invalid JSON lines are skipped and scanning continues. Partial corruption in a source file therefore becomes missing turn rows rather than a hard failed scan. (`src-tauri/src/sessions/mod.rs:89-125`)
14. The single-row insert path and batch insert path do not persist the same fields; single-row ingestion drops parent and sidechain state. (`src-tauri/src/state/db.rs:1948-1977`, `src-tauri/src/state/db.rs:1998-2026`)
15. The adapter contract is "format-agnostic", so upstream JSONL format drift is isolated to scripts, but the reference Claude script currently hard-filters only `user` and `assistant` records. Summary/compaction/system records are silently ignored. (`src-tauri/src/sessions/mod.rs:1-18`, `scripts/claude-code-turns:68-83`)
16. Corrupted or partially written JSONL records are silently skipped by the reference scripts. That preserves scan progress but loses evidence needed for exact transcript reconstruction. (`scripts/claude-code-turns:57-86`, `scripts/codex-turns:56-89`)
17. Codex ingestion currently ignores `.jsonl.zst` files because the reference script globs only `rollout-*.jsonl`. (`scripts/codex-turns:41-50`)
18. Direct CLI sessions can enter `session_turns` through ingestion, but the runner has no model provenance for them. Today they can only be resumed if the caller supplies a model whose pool includes the inferred owner; there is no current-state path to infer the model from those turns. (`src-tauri/src/main.rs:117-123`, `src-tauri/src/main.rs:843-876`)
19. `provider_quotas.exhausted_at` is provider-account global. It is independent of model pools and independent of sessions; any migration trigger that reads it is consuming account state, not conversation state. (`src-tauri/src/state/db.rs:63-74`, `src-tauri/src/state/db.rs:1297-1316`)
20. When every provider in a pool is marked exhausted, `select_provider` still returns an index: the oldest exhausted account. That is intentional current behavior, but it means "exhausted" is not a hard no-spawn state. (`src-tauri/src/balancer/mod.rs:90-108`, `src-tauri/src/balancer/mod.rs:617-640`)
21. `score_by_density` interleaves refresh/scanning side effects, projection math, fallback behavior, and final selection. The projected window values are not inspectable by migration code without refactoring the current private flow. (`src-tauri/src/balancer/mod.rs:49-65`, `src-tauri/src/balancer/mod.rs:121-244`)
22. `quota_check` can show selected provider and cached windows, but it does not expose the same binding score or projected per-window usage that `score_by_density` computes internally. (`src-tauri/examples/quota_check.rs:103-147`, `src-tauri/src/balancer/mod.rs:216-219`)
23. Trace is invocation-tree scoped. It can count turns for one invocation's `(provider, session_id)`, but it does not aggregate multiple provider segments or sibling sessions under a conversation identity. (`src-tauri/src/trace/mod.rs:152-220`, `src-tauri/src/trace/mod.rs:276-292`)
24. Trace transcript state can say `no_locator`, `missing`, or `available`, but resume lookup does not consult transcript locator state. A session can be "found" for resume by `session_turns` while the raw transcript path remains unavailable to trace. (`src-tauri/src/state/db.rs:2069-2081`, `src-tauri/src/trace/mod.rs:294-371`)
25. The current `providers` aggregate table is keyed by `(model_name, provider_index)`, while quota state is keyed by `provider_name`. Adjacent routing and migration consumers have to account for those different identity scopes. (`src-tauri/src/state/db.rs:377-406`, `src-tauri/src/state/db.rs:1202-1238`)
26. `recent_error_count` counts all recent failed invocations for a model/provider index; it does not filter by `error_category`. Density scoring therefore treats quota and non-quota recent failures the same for this avoidance branch. (`src-tauri/src/state/db.rs:1240-1260`, `src-tauri/src/balancer/mod.rs:151-162`)
27. `mark_exhausted` is called on non-interactive direct-model failure when diagnostics classify stderr as quota exhausted. Interactive `run_repl` failures finalize without running diagnostics, so exhausted marking is not symmetric across execution modes. (`src-tauri/src/main.rs:796-807`, `src-tauri/src/main.rs:1064-1075`)

The current trace walker protects against cycles and depth overflow at the invocation-tree layer only. (`src-tauri/src/trace/mod.rs:115-135`, `src-tauri/src/trace/mod.rs:183-217`)

## 4. Currently Supported / User-Reachable Paths

1. `agents repl <model>` with no resume opens the state DB, loads configs, selects a provider through `select_provider`, starts an invocation row, launches interactive args, finalizes the row, and attempts post-exit session ingestion. It must keep working without any chain input. (`src-tauri/src/main.rs:630-727`, `src-tauri/src/main.rs:759-810`)
2. `agents repl <model> --resume <UUID>` validates a full UUID, resolves the provider by current session-id lookup, requires the provider in the model pool, requires `[providers.resume]`, records `session_capture_method = "resumed"`, launches the interactive CLI, and emits the target session ID on success. (`src-tauri/src/main.rs:663-724`, `src-tauri/src/main.rs:751-792`)
3. `agents resume -m <model> --session-id <UUID> -f <file>` validates UUID, resolves an answer payload, resolves the provider by current session-id lookup, records the attempted session before spawn, launches one-shot resume, records resume acceptance, runs diagnostics on failure, and writes stdout on success. (`src-tauri/src/main.rs:813-980`)
4. `agents -m <model> --resume <UUID> "prompt"` is routed by top-level prompt detection into `run_resume`; today it cannot omit `-m`. (`src-tauri/src/main.rs:313-352`)
5. `agents --resume <UUID>` with no prompt and `-m <model>` is routed into `run_repl`; today it cannot omit `-m`. (`src-tauri/src/main.rs:318-321`, `src-tauri/src/main.rs:353-359`)
6. `agents trace <invocation_uuid>` walks one invocation tree from a recorded UUID and renders either JSON or ASCII. It currently reports session state per invocation row, not per chain. (`src-tauri/src/main.rs:265-279`, `src-tauri/src/trace/mod.rs:98-150`)
7. Direct CLI usage outside agent-runner is user-reachable through session ingestion. Those turns affect quota projection and resume owner lookup when scripts are configured, but no invocation row carries their model. 8. `cargo run --example session_scan --release` is a supported diagnostic path for manually exercising ingestion and seeing provider-level assistant-turn counts. (`src-tauri/examples/session_scan.rs:1-74`)
9. `cargo run --example quota_check --release` is a supported diagnostic path for refreshing quota and seeing current balancer picks. (`src-tauri/examples/quota_check.rs:1-15`, `src-tauri/examples/quota_check.rs:47-147`)
10. GUI `test_model` is user-reachable through Tauri. It selects a provider and can mark exhaustion, but it is not a resume or chain path today. (`src-tauri/src/lib.rs:480-515`)
11. Session ingestion through ordinary balanced execution is user-reachable whenever `select_provider` receives a `BalanceContext`; it scans each provider before scoring. (`src-tauri/src/balancer/mod.rs:49-65`, `src-tauri/src/main.rs:995-1017`)
12. Post-success session capture through `ingest_and_emit_session_id` is user-reachable for direct model, agent, one-shot resume, and REPL flows; failure to emit leaves the invocation finalized but less observable. (`src-tauri/src/main.rs:771-792`, `src-tauri/src/main.rs:955-973`, `src-tauri/src/main.rs:1087-1104`)

## 5. Migration Path Implications

1. Pre-backfill state today consists of `session_turns` rows and `invocations.session_id` values. There is no chain table, no segment table, and no place to record active segment, transition reason, or last turn at switch time. (`src-tauri/src/state/db.rs:493-505`, `src-tauri/src/state/db.rs:1182-1199`)
2. The first-open backfill described by the proposal would consume existing distinct `(provider_name, session_id)` facts from `session_turns` plus model provenance from invocation rows. Current UI/direct sessions may lack invocation provenance entirely. (`proposals/05-session-migration.md:62-71`, `src-tauri/src/state/db.rs:2069-2079`)
3. The current SQLite open path already does synchronous schema work before returning. Adding a 100K-row chain backfill would happen on the same critical open path unless split into an explicit command. (`src-tauri/src/state/db.rs:365-514`)
4. `exhausted_at` is per-provider-global while proposed chain segments are per `(chain, provider, session)`. If a provider becomes exhausted mid-conversation today, the only current state is the global flag and the invocation row failure; there is no current segment boundary to record that the conversation should move. (`src-tauri/src/state/db.rs:1297-1316`, `src-tauri/src/main.rs:1071-1075`)
5. A successful non-empty quota refresh clears `exhausted_at` globally, regardless of any individual session's history. Any future chain-level decision inherits that global clear semantics. (`src-tauri/src/state/db.rs:1447-1458`)
6. Current direct CLI sessions are already counted by provider for quota projection. They are not grouped by logical conversation beyond provider/session ID. (`src-tauri/src/state/db.rs:2164-2191`)
7. Existing `session_turns` uniqueness is per provider/session/turn, so the same upstream UUID can already appear under multiple providers without violating constraints. Today that shape is treated as multiple resolver matches, not a ledger. (`src-tauri/src/state/db.rs:493-505`, `src-tauri/src/state/db.rs:2069-2081`)
8. Existing invocation rows may contain `session_id = NULL`, `session_capture_method = "none"`, or `session_capture_method = "failed"`. Those rows do not provide enough current-state data to seed a chain segment without additional evidence. (`src-tauri/src/state/db.rs:1182-1199`, `src-tauri/src/trace/mod.rs:241-255`)
9. Legacy invocation migration can produce `status = "legacy"` rows with `provider_name = NULL` when model config cannot resolve provider names during DB open. Those rows are already tolerated by trace, but they are weak model/session provenance for backfill. (`src-tauri/src/state/db.rs:901-929`, `src-tauri/src/trace/mod.rs:258-273`)

## 6. Observability Gaps That Exist Today

1. There is no CLI or GUI surface that lists "sessions that are mine across providers"; README points users to ad-hoc SQL for questions outside `trace`. (`README.md:478-485`)
2. `trace` shows one invocation tree and one invocation's session state at a time; it does not aggregate by conversation chain or show segment history. (`src-tauri/src/trace/mod.rs:152-220`)
3. `quota_check` shows provider picks and window percentages, but not session density, chain density, migration thresholds, or the turns driving projected usage. (`src-tauri/examples/quota_check.rs:103-147`)
4. Session ingestion reports script lines, new rows, and errors, but not missing/corrupted source lines beyond adapter-specific stderr or skipped-line behavior. (`src-tauri/src/sessions/mod.rs:45-57`, `src-tauri/examples/session_scan.rs:44-56`)
5. Resume ambiguity is only observable as a non-TTY detail line; there is no structured ambiguity report or preview. (`src-tauri/src/main.rs:586-597`, `src-tauri/src/main.rs:681-690`)
6. Compaction boundaries are not observable in SQLite today. Current turn counts include all ingested assistant/user turns, with no "live state after compaction" view. (`src-tauri/src/state/db.rs:2036-2060`)
7. There is no structured output that says which provider owns a session before attempting resume. The owner is visible only through resume stderr or manual SQL against `session_turns` / `invocations`. (`src-tauri/src/main.rs:677-690`, `src-tauri/src/state/db.rs:2069-2081`)
8. There is no trace field that identifies which provider's local transcript file is canonical when the same session ID has multiple provider matches. Trace only receives the invocation row's provider/session pair. (`src-tauri/src/trace/mod.rs:258-337`)
9. There is no durable event for "session ingestion scan failed" beyond warnings printed by callers and `ScanReport.errors` returned in-process. (`src-tauri/src/sessions/mod.rs:45-57`, `src-tauri/src/main.rs:538-541`)
