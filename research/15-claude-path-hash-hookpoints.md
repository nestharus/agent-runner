## 1. Reuse Points

- Reuse the existing migration stderr writer instead of introducing logging. `migrate_chain_segment` already receives `stderr: &mut dyn Write` (src-tauri/src/migration/mod.rs:84-93) and writes the operational `[migrate]` line through that sink (src-tauri/src/migration/mod.rs:232-242). The proposal's canonicalize warning channel explicitly wants this same stream (proposals/15-claude-path-hash.md:109-127). The implementation hook is to change the local encoder call at src-tauri/src/migration/mod.rs:161 to pass `stderr`, and to use the same `writeln!`/`MigrationError::Io { path: "<stderr>", ... }` pattern already used at src-tauri/src/migration/mod.rs:232-242.

- There is no standardized path-to-string helper in the migration module beyond the current encoder and a test-only duplicate. `rg` finds `to_string_lossy()` in the production encoder at src-tauri/src/migration/mod.rs:264 and the inline test helper at src-tauri/src/migration/mod.rs:319-320. The implementation should keep using `Path::to_string_lossy()` because the proposal commits to that input shape (proposals/15-claude-path-hash.md:81-94), but should not add another generic helper unless it replaces the duplicate slash-only helper.

- Reuse the existing `MigrationError::SpawnCwdUnsupported { provider, cwd }` variant for empty cwd only. The variant is defined at src-tauri/src/migration/mod.rs:27-30; current code triggers it for empty or non-absolute cwd at src-tauri/src/migration/mod.rs:256-262. The proposal keeps the variant and narrows the trigger to `cwd.as_os_str().is_empty()` (proposals/15-claude-path-hash.md:96-107, proposals/15-claude-path-hash.md:131-136).

- Reuse existing Claude migration fixture builders rather than adding a parallel harness. Inline unit fixtures already build a two-provider Claude model at src-tauri/src/migration/mod.rs:290-317, seed source JSONL at src-tauri/src/migration/mod.rs:323-339, and exercise `migrate_chain_segment` with captured `Vec<u8>` stderr at src-tauri/src/migration/mod.rs:389-400 and src-tauri/src/migration/mod.rs:430-441. The WU-14-02 RCA fixture already has an authoritative expected encoder at src-tauri/tests/claude_path_hash_rca/mod.rs:129-141, Windows-shaped path fixture at src-tauri/tests/claude_path_hash_rca/mod.rs:125-127, and symlink fixture at src-tauri/tests/claude_path_hash_rca/mod.rs:143-155.

- Reuse the existing RCA tests as the main post-fix integration contract. RC-1 asserts target path equality for non-alnum paths at src-tauri/tests/claude_path_hash_rca/rc1_non_alnum_encoding.rs:13-22; RC-2 asserts Windows-shaped encoding and target path equality at src-tauri/tests/claude_path_hash_rca/rc2_windows_backslash_encoding.rs:11-24; RC-3 asserts resolved symlink target placement at src-tauri/tests/claude_path_hash_rca/rc3_symlink_canonicalization.rs:10-28.

## 2. Extension Points

- The single product edit point is `claude_project_dir_for`, currently defined as `pub(crate) fn claude_project_dir_for(provider: &str, cwd: &Path) -> Result<String, MigrationError>` at src-tauri/src/migration/mod.rs:256. Its body currently rejects empty or host-non-absolute paths at src-tauri/src/migration/mod.rs:257-262 and then applies slash-only encoding at src-tauri/src/migration/mod.rs:264.

- The only production caller is the migration write path at src-tauri/src/migration/mod.rs:161. That caller feeds the result directly into `projects_dir.join(&cwd_project_dir)` at src-tauri/src/migration/mod.rs:188 and returns the actual written path as `MigratedSegment.target_jsonl_path` at src-tauri/src/migration/mod.rs:244-253. This preserves the ticket's Code Boundary claim that the writer path is the only production hookpoint (research/15-claude-path-hash-problem-map.md:5-24).

- The adjacent seam is `migrate_chain_segment`'s stderr contract. The encoder currently has no stderr parameter, but `migrate_chain_segment` already has one (src-tauri/src/migration/mod.rs:84-93), and the proposal's pseudocode changes the encoder shape to accept that warning sink (proposals/15-claude-path-hash.md:65-90). Inline tests that call the helper directly at src-tauri/src/migration/mod.rs:463-487 will need a local `Vec<u8>` sink once the signature changes.

- Adjacent code expects `MigratedSegment.target_jsonl_path` to be the path actually written. The migration writer creates the target directory at src-tauri/src/migration/mod.rs:188-194, writes and renames the JSONL at src-tauri/src/migration/mod.rs:195-214, and returns the same path at src-tauri/src/migration/mod.rs:244-253. The proposal explicitly forbids rewriting that contract (proposals/15-claude-path-hash.md:27-30).

- `std::fs::canonicalize` is the right symlink resolver for this hookpoint. Rust's official stable docs describe it as returning a canonical absolute path with symbolic links resolved, mapping to `realpath` on Unix and `CreateFile` plus `GetFinalPathNameByHandle` on Windows; on Windows it converts to extended-length path syntax. That matches the proposal's "canonicalize first, no cfg-gated custom resolver" design (proposals/15-claude-path-hash.md:27-32, proposals/15-claude-path-hash.md:111-127) and the RCA's real-Claude symlink probe (research/15-claude-path-hash-rca.md:42-55). Source: https://doc.rust-lang.org/stable/std/fs/fn.canonicalize.html

## 4. Deletion Candidates

- Delete the `Path::is_absolute()` branch inside `claude_project_dir_for`. The current combined condition is at src-tauri/src/migration/mod.rs:257; the proposal says only empty cwd should return `SpawnCwdUnsupported` (proposals/15-claude-path-hash.md:96-107, proposals/15-claude-path-hash.md:131-136). No other production code refers to `SpawnCwdUnsupported`, and `rg` finds it only at the variant definition, the encoder return, and inline tests (src-tauri/src/migration/mod.rs:27-30, src-tauri/src/migration/mod.rs:256-264, src-tauri/src/migration/mod.rs:472-493).

- Replace the old slash-only encoder body at src-tauri/src/migration/mod.rs:264 with the canonicalize-then-filter rule from the RCA (research/15-claude-path-hash-rca.md:31-37) and proposal (proposals/15-claude-path-hash.md:65-90). This makes the literal `cwd.to_string_lossy().replace('/', "-")` expression obsolete for target path derivation.

- Replace or remove `claude_project_dir_for_rejects_relative_path`. It currently asserts relative paths are rejected at src-tauri/src/migration/mod.rs:472-480, but the approved design removes host-shape rejection and leaves only empty cwd rejection (proposals/15-claude-path-hash.md:96-107). A better successor test is a canonicalize-failure fallback test with captured stderr, matching the proposal's warning contract (proposals/15-claude-path-hash.md:109-127).

- Keep `MigrationError::SpawnCwdUnsupported`. The proposal chooses the "kept variant, narrowed trigger" path (proposals/15-claude-path-hash.md:96-107), and the empty-cwd inline test at src-tauri/src/migration/mod.rs:485-493 remains a useful assertion after its direct-call signature is updated.

- The inline test helper `claude_project_dir_name` at src-tauri/src/migration/mod.rs:319-320 is a partial deletion/replacement candidate. It is only a source/expected-path helper for inline tests (src-tauri/src/migration/mod.rs:323-339, src-tauri/src/migration/mod.rs:403-409, src-tauri/src/migration/mod.rs:444-449). Any expected target path derived from it should use the new encoder or a test helper that implements the full rule; source seeding can stay if the fixture is intentionally modeling legacy slash-only source discovery, but that intent should be explicit.

## 5. Caller-Graph Verification

`rg 'claude_project_dir_for'` in the worktree currently enumerates:

- Production call: src-tauri/src/migration/mod.rs:161 derives `cwd_project_dir` in `migrate_chain_segment`.
- Definition: src-tauri/src/migration/mod.rs:256 defines `claude_project_dir_for`.
- Inline tests: src-tauri/src/migration/mod.rs:463-487 call the helper directly.

No caller outside the product Code Boundary relies on `MigrationError::SpawnCwdUnsupported` rejecting non-Unix shapes. `rg 'SpawnCwdUnsupported'` finds only the enum variant at src-tauri/src/migration/mod.rs:27-30, the current encoder return at src-tauri/src/migration/mod.rs:257-262, and inline rejection tests at src-tauri/src/migration/mod.rs:472-493. The only production path is the migration write path named by the ticket and problem map (research/15-claude-path-hash-problem-map.md:5-24).

`std::fs::canonicalize` requires no production `#[cfg]` branch for this implementation. The current encoder path has no `#[cfg(target_os)]` code (src-tauri/src/migration/mod.rs:256-265), the proposal forbids platform-specific custom handling (proposals/15-claude-path-hash.md:27-32), and Rust's official docs provide the intended platform behavior through the standard API. The existing RCA symlink test remains `#[cfg(unix)]` only because it creates Unix symlinks at src-tauri/tests/claude_path_hash_rca/mod.rs:143-155 and is declared Unix-only at src-tauri/tests/claude_path_hash_rca/mod.rs:15-16.

The inline tests at src-tauri/src/migration/mod.rs:463-493 are the direct tests to update: strengthen `claude_project_dir_for_encodes_absolute_unix_path` at src-tauri/src/migration/mod.rs:463-468, replace the relative rejection test at src-tauri/src/migration/mod.rs:472-480, and keep the empty-cwd rejection test at src-tauri/src/migration/mod.rs:485-493. The WU-14-02 RCA integration tests under `src-tauri/tests/claude_path_hash_rca/` are already the correct post-fix contract tests (src-tauri/tests/claude_path_hash_rca/mod.rs:12-16, src-tauri/tests/claude_path_hash_rca/rc1_non_alnum_encoding.rs:7-23, src-tauri/tests/claude_path_hash_rca/rc2_windows_backslash_encoding.rs:6-24, src-tauri/tests/claude_path_hash_rca/rc3_symlink_canonicalization.rs:7-28).

The WU-14-01 integration tests under `src-tauri/tests/session_migration_rca/` are not safe to assume green unchanged. They validate the cwd-mismatch contract, but they also embed slash-only expected target lookup at src-tauri/tests/session_migration_rca/rc1_cwd_project_dir_mismatch.rs:33-41 and slash-only fake-Claude lookup at src-tauri/tests/session_migration_rca/mod.rs:109-115. This is the hookpoint finding that triggers return-to-Phase-2.5 rather than proceeding directly to implementation.
