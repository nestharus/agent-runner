# Initiative 06 / 06-locate — Existing-State Risk Profile

## 1. Touched Surface Inventory

1. `Cli` already owns top-level `--resume`, `--migrate`, `-m/--model`, `-f/--file`, `-p/--project`, and config-dir flags. `args_conflicts_with_subcommands = true` means top-level execution and subcommand forms are mutually exclusive at clap parse time. (`src-tauri/src/main.rs:20-76`)
2. `Subcommands` currently has `trace`, `repl`, `resume`, hidden `resume-list`, `migrate-db`, and `migrate-config`. There is no `session` command group today. (`src-tauri/src/main.rs:77-166`)
3. Top-level dispatch matches each existing subcommand directly and routes `trace`, `repl`, `resume`, `resume-list`, `migrate-db`, and `migrate-config` before any top-level prompt/model execution. (`src-tauri/src/main.rs:287-338`)
4. Top-level `--resume <UUID>` is a separate supported dispatch path: prompt/file/stdin presence routes to `run_resume`; no prompt routes to `run_repl`. (`src-tauri/src/main.rs:341-389`)
5. `run_trace_command` opens the default state DB, loads `sessions.toml`, builds a trace report, and emits either pretty JSON to stdout or ASCII to stdout. Missing invocation is stderr plus exit `1`; other errors bubble as command errors. (`src-tauri/src/main.rs:447-478`)
6. `run_resume` validates `session_id` as a full UUID before reading the answer payload or opening state, then opens the default DB, loads models, providers, and sessions config, and calls `StateDb::resolve_resume`. (`src-tauri/src/main.rs:1056-1088`)
7. `run_resume` converts `resolve_resume` errors to human stderr, resolves an execution target from provider config, optionally migrates the active segment, requires `[providers.resume]`, records an invocation, and spawns the provider. (`src-tauri/src/main.rs:1087-1199`)
8. `run_repl` opens the default DB and configs, calls `StateDb::resolve_resume` when `--resume` is present, derives a fallback provider target when no model is known, and otherwise performs ordinary provider selection. (`src-tauri/src/main.rs:809-878`)
9. `run_repl` uses the resolved active provider/session, can run migration before spawn, requires `interactive_args`, records an invocation, and writes `session_capture_method = "resumed"` with the user-supplied resume id before launching. (`src-tauri/src/main.rs:887-990`)
10. `ResolvedResume` is the current ownership shape: `chain_id`, optional `model_name`, optional `ModelConfig`, `active_provider`, and `active_session_id`. It does not carry transcript path, storage type, workspace root, quota state, or mutability. (`src-tauri/src/state/db.rs:131-138`)
11. `ResumeError` has typed states for invalid UUID, no chain, ambiguity, provider/model mismatch, unknown model, missing active segment, unconfigured provider, missing resume strategy, and DB errors. (`src-tauri/src/state/db.rs:140-166`)
12. `StateDb::resolve_resume` accepts a UUID-shaped input, finds candidate chains where `session_id = input OR chain_id = input`, chooses one chain, reads the active segment, infers model name from latest invocation or chain metadata, validates active provider membership when a model is known, and returns `ResolvedResume`. (`src-tauri/src/state/db.rs:2577-2670`)
13. `candidate_chain_ids` reads only `session_chain_segments`; `session_turns` and `invocations` are not directly consulted during candidate selection. (`src-tauri/src/state/db.rs:2696-2711`)
14. `choose_resume_chain` returns a single chain immediately for one match. For multiple matches it selects the only chain used in the last 24 hours, selects the most recently used chain when none are recent, and returns ambiguity when more than one recent chain exists. (`src-tauri/src/state/db.rs:2713-2749`)
15. `active_segment_for_chain` reads the latest `ended_at IS NULL` segment for a chain, ordered by `started_at DESC, id DESC`. Multiple active segments are tolerated by picking the latest row. (`src-tauri/src/state/db.rs:2751-2764`)
16. `chain_previews` backs the hidden `resume-list` and ambiguity output by reading each candidate chain, its active segment, active turn count, and the last three turns. (`src-tauri/src/state/db.rs:2794-2856`, `src-tauri/src/main.rs:1887-1900`)
17. `StateDb::open` creates the parent directory, opens SQLite read/write, sets WAL, ensures invocation/session/quota schemas, creates `session_turns`, `session_chains`, and `session_chain_segments`, then runs `backfill_session_chains` on every open. (`src-tauri/src/state/db.rs:431-608`)
18. `open_default` reads from `dirs::data_dir()/oulipoly-agent-runner/state.db`; the README documents this as `~/.local/share/oulipoly-agent-runner/state.db` on typical Linux systems. (`src-tauri/src/state/db.rs:611-615`, `README.md:224-224`)
19. `session_turns` stores provider, session, turn id, timestamp, role, parent turn, sidechain, compaction-boundary, source file, and ingested timestamp, with uniqueness on `(provider_name, session_id, turn_id)`. (`src-tauri/src/state/db.rs:559-572`)
20. `session_chains` stores one logical chain id with timestamps and `model_name`; `session_chain_segments` stores provider/session segments with nullable `ended_at`, `last_turn_id`, and transition reason constrained to `initial`, `manual`, `quota_threshold`, `exhausted`, or `imported`. (`src-tauri/src/state/db.rs:574-592`, `src-tauri/src/balancer/mod.rs:54-70`)
21. The session indexes currently cover segment lookup by `session_id`, active segment lookup by `(chain_id, ended_at)`, turn lookup by provider/timestamp and session/timestamp, and invocation lookup by provider/session. (`src-tauri/src/state/db.rs:594-597`, `src-tauri/src/state/db.rs:846-877`)
22. Batch ingestion inserts `session_turns` with `source_file = ''` and persists parent, sidechain, and compaction flags; per-row ingestion has a `source_file` parameter and writes compaction state but not parent/sidechain. (`src-tauri/src/state/db.rs:2137-2164`, `src-tauri/src/state/db.rs:2171-2228`)
23. `scan_provider` runs the configured `turn_script`, parses normalized JSONL, batch-ingests rows, and then calls `mint_imported_chain_if_absent` for each turn using model `"<unknown>"`. Script failures and malformed lines become `ScanReport.errors`. (`src-tauri/src/sessions/mod.rs:55-141`)
24. `backfill_session_chains` is skipped when any `session_chains` row exists. Otherwise it groups all existing `session_turns` by `(provider_name, session_id)`, infers a model from latest invocation with that `session_id`, mints one imported chain and one active segment per group, and records the latest turn id. (`src-tauri/src/state/db.rs:2256-2363`)
25. `mint_chain_for_invocation_session` mints chain/segment state from an invocation row that has provider and session columns; it is called by `emit_known_session_id`. (`src-tauri/src/state/db.rs:1205-1228`, `src-tauri/src/main.rs:594-615`)
26. `[providers.session_storage]` is represented as `SessionStorage::{ClaudeCode { projects_dir }, Codex { sessions_dir }}` with serde tag `kind` and snake-case names. There is no `other` enum variant today. (`src-tauri/src/config/model.rs:195-229`)
27. Runtime provider config in `providers.toml` carries `session_storage`; model TOMLs now reject old per-provider runtime blocks, including `session_storage`, and `providers.toml` expands leading tildes during load. (`src-tauri/src/config/providers.rs:10-32`, `src-tauri/src/config/providers.rs:81-105`, `src-tauri/src/config/model.rs:580-633`)
28. `ProvidersConfig::effective_provider` and `runtime_provider` copy runtime `session_storage` into the effective `ProviderConfig` used by resume, balancing, and migration. (`src-tauri/src/config/providers.rs:116-134`, `src-tauri/src/config/providers.rs:157-190`)
29. Storage discrimination is implicit in enum variants and in migration/balancer checks. Migration currently rejects any source or target with `SessionStorage::Codex` and only has a Claude storage fallback finder. (`src-tauri/src/migration/mod.rs:112-153`, `src-tauri/src/migration/mod.rs:256-271`)
30. `SessionsConfig` is separate from provider storage config. It declares `turn_script`, optional `transcript_locator`, and optional adapter `state_dir`, keyed by provider name. (`src-tauri/src/config/sessions.rs:6-25`)
31. `locate_transcript` uses `sessions.toml`, not `[providers.session_storage]`: absent provider entry or absent locator returns `Ok(None)`, otherwise it creates the adapter state dir, runs the locator with `SESSION_ID`, and requires exactly one non-empty stdout line. (`src-tauri/src/sessions/mod.rs:171-199`)
32. The shared script runner invokes `sh -c`, sets `STATE_DIR` and optionally `SESSION_ID`, drains stdout/stderr concurrently, enforces a 600s timeout, and turns non-zero exit into an error string containing stderr. (`src-tauri/src/sessions/mod.rs:201-277`)

35. `compose_resume_args` and provider resume composition currently ignore `target_jsonl_path`; `flag` appends `<flag> <session_id>`, and `subcommand` appends `<subcommand...> <session_id>`. (`src-tauri/src/executor/cli.rs:276-327`)

## 2. Currently Risky or Brittle Behavior

1. Ambiguity is time-window dependent. Multiple chains for one UUID become a single automatic answer when exactly one is recent or when none are recent; only multiple recent chains become `ResumeError::Ambiguous`. (`src-tauri/src/state/db.rs:2713-2749`)
2. Resolver candidate selection ignores raw `session_turns` rows unless they already have segment membership. The candidate query reads `session_chain_segments` only. (`src-tauri/src/state/db.rs:2696-2711`)
3. `backfill_session_chains` skips entirely when any chain row exists, so partially backfilled DBs can contain turn rows that are not made resolvable by the open-path backfill. (`src-tauri/src/state/db.rs:2256-2271`)
4. New scanned turns receive chain membership through `mint_imported_chain_if_absent`, but failures are appended to `ScanReport.errors`; callers often continue with stale or incomplete state. (`src-tauri/src/sessions/mod.rs:125-141`, `src-tauri/src/balancer/mod.rs:98-113`)
5. Multiple active segments in one chain are not treated as a resolver error. `active_segment_for_chain` picks the latest active segment by time/id. (`src-tauri/src/state/db.rs:2751-2764`)
6. Ingested sessions whose underlying JSONL file was renamed, deleted, or corrupted can still resolve for resume because `resolve_resume` reads chain tables, not the transcript locator or provider storage. (`src-tauri/src/state/db.rs:2577-2670`, `src-tauri/src/trace/mod.rs:318-364`)
7. Trace reports a missing located path as `transcript_state = "missing"` and drops `transcript_path`; locator errors also become warnings plus `missing`. The returned path is not preserved in the missing state. (`src-tauri/src/trace/mod.rs:349-380`)
8. `locate_transcript` treats empty stdout and multi-line stdout as errors, not `Ok(None)`. Missing locator config returns `Ok(None)`, while a reference locator that exits `1` for not found becomes an error. (`src-tauri/src/sessions/mod.rs:171-199`, `scripts/claude-code-locate-transcript:47-48`)
9. Locator paths are accepted as `PathBuf` without canonicality or absoluteness checks in trace; README asks scripts to print an absolute path, but current `locate_transcript` does not enforce it. (`src-tauri/src/sessions/mod.rs:187-198`, `README.md:384-384`)
10. The 600s shared script timeout is generous enough for first scans, but trace-time locator calls inherit the same timeout as turn scans. (`src-tauri/src/sessions/mod.rs:27-30`, `src-tauri/src/sessions/mod.rs:241-252`)
11. Storage-type naming is split between code and requested external vocabulary: current serde kinds are `claude_code` and `codex`, while the harness request names `codex_session`. Current code has no user-facing stable `storage_type` field. (`src-tauri/src/config/model.rs:195-200`, `/home/nes/projects/agent-harness/tmp/scratch/agent-runner-feature-requests/01-session-locate.md:22-36`)
12. Providers without `session_storage` are common and valid today. They can still be resumable when they have `[providers.resume]` and chain state, but there is no current storage-type answer for them. (`src-tauri/src/config/providers.rs:35-48`, `src-tauri/src/main.rs:1154-1162`)
13. `SessionStorage::Codex` is considered storage-bearing by migration target selection but actual migration of Codex storage is explicitly deferred. (`src-tauri/src/balancer/mod.rs:399-429`, `src-tauri/src/migration/mod.rs:112-118`)
14. `workspace_root` has no explicit persisted field. Current nearby signals are the `-p/--project` working directory used for provider spawn, Claude's project-hash directory derived from transcript path during migration, and provider JSONL paths. (`src-tauri/src/main.rs:60-62`, `src-tauri/src/executor/cli.rs:329-345`, `src-tauri/src/migration/mod.rs:155-195`)
15. `source_file` exists on `session_turns`, but batch ingestion writes it as an empty string, so scanned turns generally do not preserve raw transcript path provenance in the DB. (`src-tauri/src/state/db.rs:559-570`, `src-tauri/src/state/db.rs:2188-2201`)
16. The current "mutable" signals are indirect: active segment exists, provider is configured, provider belongs to a known model or runtime config, provider has `[providers.resume]`, optional resume acceptance from a prior invocation, and quota exhaustion state. None is a single session-writable field. (`src-tauri/src/state/db.rs:2751-2764`, `src-tauri/src/main.rs:1154-1162`, `src-tauri/src/state/db.rs:1187-1203`)
17. `exhausted_at` is provider-account global, not session scoped. Migration can react to it, but resume still can spawn an exhausted provider when no migration target is selected. (`src-tauri/src/balancer/mod.rs:367-383`, `src-tauri/src/main.rs:1120-1155`)
18. `compose_resume_args` accepts `target_jsonl_path` but ignores it for both supported strategies. Current resume mutability cannot be inferred from an argument strategy that uses a canonical file path. (`src-tauri/src/executor/cli.rs:276-327`)
19. `run_resume` records the caller's `session_id` as `"resumed"` before spawn, while the actual provider target can be `resolved.active_session_id` after chain resolution or migration. Trace warns when acceptance is not accepted. (`src-tauri/src/main.rs:1181-1198`, `src-tauri/src/trace/mod.rs:234-240`)
20. Direct CLI ingestion is cursor-script based. The reference scripts skip malformed JSON and unreadable files, then advance cursor by file mtime, making some corruption or read errors observable only as absent turns. (`scripts/claude-code-turns:42-88`, `scripts/codex-turns:41-89`)
21. Reference transcript locators perform filename matching and content fallback, but silently skip malformed JSON and unreadable files during fallback. (`scripts/claude-code-locate-transcript:39-66`, `scripts/codex-locate-transcript:33-63`)
22. `StateDb::open` is not read-only. It creates directories, sets WAL, ensures schemas, and runs chain backfill before returning, so every current resolver read also has schema/backfill side effects. (`src-tauri/src/state/db.rs:431-608`)
23. Config load failure behavior differs by path. `run_trace_command` treats malformed `sessions.toml` as a command error, while resume paths load providers/sessions with `unwrap_or_default` and can degrade to missing runtime/session config. (`src-tauri/src/main.rs:447-458`, `src-tauri/src/main.rs:1079-1084`)
24. GUI and CLI state DB paths diverge today. A session visible to CLI `open_default` is not necessarily visible to a Tauri command opened beside `models_dir`, and vice versa. (`src-tauri/src/state/db.rs:611-615`, `src-tauri/src/lib.rs:525-533`)
25. Current hidden `resume-list` validates only a full UUID and prints chain previews; it does not validate provider storage or transcript path state. (`src-tauri/src/main.rs:1887-1900`, `src-tauri/src/main.rs:2004-2014`)

## 3. Adjacent Surfaces in Blast Radius

1. `agents resume`, `agents repl --resume`, and top-level `--resume` all consume `StateDb::resolve_resume`, `resume_execution_target`, and provider resume strategy. (`src-tauri/src/main.rs:341-389`, `src-tauri/src/main.rs:718-755`, `src-tauri/src/main.rs:1056-1263`)
2. Existing resume stderr formatting is adjacent because it exposes invalid UUID, not found, ambiguity, mismatch, missing provider, and missing resume states today. (`src-tauri/src/main.rs:658-707`)
3. `migrate-config` is adjacent only as a config boundary: it owns movement of runtime blocks into `providers.toml`, including `session_storage`, and is not a session resolver. (`src-tauri/src/main.rs:1472-1488`, `src-tauri/src/main.rs:1599-1765`)
4. `trace --json` is the closest overlapping JSON surface. It is invocation-tree scoped and reports a per-node `TraceSession`; it is not an owner lookup by session id. (`src-tauri/src/trace/mod.rs:23-80`, `src-tauri/src/trace/mod.rs:223-382`)
5. Initiative 05 chain and segment state is inside the read blast radius. The stable parts are the tables, indexes, active segment convention, and resolver shape; the recently introduced parts include compaction boundaries, migration reasons, and automatic imported-chain minting. (`src-tauri/src/state/db.rs:574-597`, `src-tauri/src/state/db.rs:2256-2575`)
6. Migration is adjacent because it uses `ResolvedResume`, `locate_transcript`, `[providers.session_storage]`, compaction boundaries, and the Claude storage fallback to copy JSONL and open a new segment. (`src-tauri/src/migration/mod.rs:79-153`, `src-tauri/src/migration/mod.rs:166-251`)
7. Adapter scripts are adjacent because ingestion and transcript path discovery are delegated to them. The runner does not parse provider-native transcript formats except for compaction backfill and migration's Claude fallback. (`src-tauri/src/sessions/mod.rs:1-18`, `scripts/README.md:65-70`, `scripts/README.md:134-149`)
8. `providers.toml` and `sessions.toml` are both in the blast radius but have different meanings: provider config declares runtime storage kind; sessions config declares executable turn and locator scripts. (`src-tauri/src/config/providers.rs:10-32`, `src-tauri/src/config/sessions.rs:6-25`)
9. The GUI/Tauri state path is adjacent only as a separate DB-location pattern. GUI commands open `state.db` next to `models_dir`, while CLI `open_default` uses the OS data directory. (`src-tauri/src/lib.rs:525-533`, `src-tauri/src/state/db.rs:611-615`)
10. Compaction backfill is adjacent because it already combines chain segments, transcript location, provider storage fallback, and raw JSONL parsing without being part of resume. (`src-tauri/src/main.rs:1909-1966`, `src-tauri/src/main.rs:1968-2001`)
11. `resume-list` is adjacent as a current chain-inspection command, but it is hidden and human-oriented. (`src-tauri/src/main.rs:155-157`, `src-tauri/src/main.rs:1887-1900`)

## 5. Migration / Pre-Existing-State Implications

1. Pre-existing `session_turns` rows become resolver-visible only through chain/segment state. Full open-path backfill mints segments only when the `session_chains` table is empty. (`src-tauri/src/state/db.rs:2256-2363`, `src-tauri/src/state/db.rs:2696-2711`)
2. Partially migrated DBs can have `session_turns` rows with no segment membership. Current `resolve_resume` returns `NoChainFound` for those session ids even though raw turn rows exist. (`src-tauri/src/state/db.rs:2577-2594`, `src-tauri/src/state/db.rs:2696-2711`)
3. Sessions on providers without `[providers.session_storage]` can appear in chains through invocation capture or turn ingestion. They are resolvable for resume if provider runtime/resume config exists, but storage kind is absent. (`src-tauri/src/main.rs:594-615`, `src-tauri/src/sessions/mod.rs:125-141`, `src-tauri/src/config/providers.rs:35-48`)
4. Sessions whose JSONL has moved or disappeared remain visible in chain state. Trace reports locator/path failure as `missing` or `no_locator`; resume proceeds from provider resume strategy and does not check path existence first. (`src-tauri/src/trace/mod.rs:318-380`, `src-tauri/src/main.rs:1154-1199`)
5. Current state DB location for CLI resolver reads is determined by `dirs::data_dir()`, which honors platform/XDG data-directory behavior. GUI commands use a different `models_dir.parent()/state.db` pattern. (`src-tauri/src/state/db.rs:611-615`, `src-tauri/src/lib.rs:525-533`)
6. Old model TOMLs containing runtime provider blocks are rejected by model load with an instruction to run `agents migrate-config`; current resolver paths that load models inherit that precondition. (`src-tauri/src/config/model.rs:580-595`, `src-tauri/src/config/model.rs:605-633`)
7. Current migration path writes target Claude JSONL under the target provider's `projects_dir` using the source path's parent directory name as `cwd_hash`; that is a storage path convention, not an explicit workspace-root record. (`src-tauri/src/migration/mod.rs:155-195`)
8. Codex storage is declared in config but copy/migration behavior is deferred, so pre-existing Codex sessions can be resumable and traceable while cross-provider storage operations reject them. (`src-tauri/src/config/model.rs:195-200`, `src-tauri/src/migration/mod.rs:112-118`)
9. Existing `invocations.session_id` rows with `session_capture_method = "none"` or `"failed"` do not mint useful chain ownership unless a concrete session id is later written. (`src-tauri/src/state/db.rs:1169-1185`, `src-tauri/src/state/db.rs:1205-1228`)
10. Imported chains minted from turn scans use `model_name = "<unknown>"`, so model inference for direct CLI sessions depends on later invocation evidence or caller override. (`src-tauri/src/sessions/mod.rs:125-134`, `src-tauri/src/state/db.rs:2616-2626`)

## 6. Observability Gaps That Exist Today

1. "Where is this session and which provider owns it" is currently answerable by SQL against chain/segment tables, by `trace --json` only after an invocation UUID is known, or by attempting `resume` and reading stderr. (`README.md:500-512`, `src-tauri/src/trace/mod.rs:59-80`, `src-tauri/src/main.rs:1116-1119`)
2. SQL exposes tables but not a stable CLI contract, not storage kind, not transcript-state normalization, and not provider-config validation. (`src-tauri/src/state/db.rs:559-597`, `src-tauri/src/config/providers.rs:81-105`)
3. `trace --json` exposes transcript state and chain id for an invocation row, but it does not resolve arbitrary session ids or aggregate all matching chains for an input. (`src-tauri/src/trace/mod.rs:223-382`)
4. Running `resume` exposes owner selection through `[resume] -> <provider>` and failure text, but it can spawn a provider and records an invocation attempt. (`src-tauri/src/main.rs:1116-1199`)
5. The hidden `resume-list` can print chain previews for a UUID, but it is human text and does not include storage kind, JSONL path, workspace root, or mutability. (`src-tauri/src/main.rs:1887-1900`, `src-tauri/src/main.rs:2004-2014`)
6. `mutable` is not observable as a single current field. Users have to compose active segment state, provider runtime config, `[providers.resume]`, prior `resume_acceptance`, path existence through trace, and provider quota/exhaustion state. (`src-tauri/src/state/db.rs:2751-2764`, `src-tauri/src/config/providers.rs:129-134`, `src-tauri/src/state/db.rs:1187-1203`)
7. Storage-type discrimination is implicit in TOML config and Rust enum matching. Trace does not emit storage type; resume does not print it; README documents storage examples but no stable field. (`src-tauri/src/config/model.rs:195-229`, `README.md:259-261`, `README.md:374-386`)
8. Workspace root is not observable from session state. Existing data exposes provider working directory at spawn time only through process behavior, and Claude project hashes are used as path segments without a DB reverse mapping. (`src-tauri/src/main.rs:60-62`, `src-tauri/src/migration/mod.rs:155-195`)
9. Transcript locator failures are observable as warnings in trace output, but not as durable DB events. (`src-tauri/src/trace/mod.rs:364-380`, `src-tauri/src/sessions/mod.rs:47-53`)
10. There is no current CLI output that displays both `chain_id` and provider storage declaration for the same session. Trace has `chain_id`; provider storage remains in config. (`src-tauri/src/trace/mod.rs:59-70`, `src-tauri/src/config/model.rs:195-229`)
11. There is no current persisted "last located transcript path" field. Every trace path lookup is lazy and can differ from a previous trace if files move or locator scripts change. (`README.md:374-386`, `src-tauri/src/trace/mod.rs:318-380`)

## 7. Assumption Register Draft

1. A1: `resolve_resume` returns exactly one match for the common single-chain, single-active-segment case. Evidence: one candidate chain returns immediately and one active segment is read by chain id. Invalidator: chain ledger state with multiple recent candidate chains or no active segment. (`src-tauri/src/state/db.rs:2713-2719`, `src-tauri/src/state/db.rs:2751-2764`)
2. A2: Ambiguity means "multiple recent chains" today, not "multiple total chains." Evidence: non-recent multi-match sets collapse to the most recent chain. Invalidator: a requirement that any multi-chain input must remain ambiguous regardless of recency. (`src-tauri/src/state/db.rs:2721-2749`)
3. A3: `transcript_locator` is sufficient to resolve a canonical JSONL path for configured Claude/Codex sessions without provider spawn. Evidence: trace calls `locate_transcript` lazily with `SESSION_ID`, and reference locators search local JSONL stores. Invalidator: a storage type whose canonical path requires provider execution, DB mutation, or network state. (`src-tauri/src/sessions/mod.rs:171-199`, `scripts/README.md:134-149`)
4. A4: `workspace_root` is derivable from current metadata or transcript path without provider spawn. Evidence: migration derives a target path from the source transcript parent directory; **Phase 5 sampling (2026-04-30) of 25 real Codex rollout files under `/home/nes/.codex/sessions/` (Codex 0.46.0 and 0.58.0) confirmed `session_meta.payload.cwd` is present in every sampled file**, so Codex workspace_root is also derivable without provider spawn. Invalidator: storage whose workspace identity is absent from path/config and only revealed by runtime provider state, or upstream Codex schema drift that removes/relocates `payload.cwd`. (`src-tauri/src/migration/mod.rs:155-195`, `research/06-locate-hookpoints.md` §I)
5. A5: Provider `session_storage` is the current source of storage-type discrimination. Evidence: storage is parsed as `SessionStorage` in provider config and propagated into effective providers. Invalidator: configured locators/scripts whose provider-native format disagrees with `[providers.session_storage]`. (`src-tauri/src/config/model.rs:195-229`, `src-tauri/src/config/providers.rs:157-190`)
6. A6: A read-only state open path can be introduced without changing the logical resolver query set. Evidence: resolver reads chain/segment/model/invocation state after open; SQLite supports read-only connections. Invalidator: current schema ensure/backfill remains a hard precondition for any correct resolver read. (`src-tauri/src/state/db.rs:431-608`, `src-tauri/src/state/db.rs:2577-2670`)
7. A7: Direct CLI sessions ingested after Initiative 05 have chain membership. Evidence: `scan_provider` calls `mint_imported_chain_if_absent` after batch insert. Invalidator: scan errors, partial DBs, or existing chain rows that cause old turn rows to remain segmentless. (`src-tauri/src/sessions/mod.rs:125-141`, `src-tauri/src/state/db.rs:2256-2271`)
8. A8: Current resume mutability can be approximated from active segment plus provider runtime/resume config, but not proven from a stored flag. Evidence: resume requires active provider target and `[providers.resume]`; no session-writable column exists. Invalidator: provider-specific storage that is readable/resumable but not writable, or writable only under a lock/state not represented today. (`src-tauri/src/state/db.rs:2751-2764`, `src-tauri/src/main.rs:1154-1162`)
